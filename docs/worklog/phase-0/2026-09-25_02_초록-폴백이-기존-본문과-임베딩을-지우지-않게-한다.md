---
title: 초록 폴백이 기존 본문과 임베딩을 지우지 않게 한다
date: 2026-09-25
area: [pipeline]
decision: PDF 다운로드 실패로 생긴 초록 폴백이 이미 저장된 본문·청크·임베딩을 덮지 못하게 하고, 리뷰에서 source 순위와 content_hash 기반 멱등 재처리로 일반화한다
---

**결정과 근거** — 감사에서 PDF 다운로드가 실패해 초록만으로 만든 결과(`fallback_abstract`)가 기존 PDF 본문을 덮어쓰는
경로를 찾았다. 저장 과정의 `DELETE FROM paper_chunks`가 `paper_embeddings`까지 cascade로 지워, 일시적 네트워크 오류 한
번이 청크와 임베딩(OpenAI 호출 비용을 들여 만든 것)을 잃게 했다. dc0981d에서 파싱된 본문이 이미 있으면 초록 폴백을
저장하지 않게 했고, 1차 리뷰(f229c59)에서 규칙을 source 순위 `layout_pdf > pdf > fallback_abstract`, 본문 `content_hash`,
청크 텍스트 비교, `--force`로 일반화했다. 리뷰 반영 세부는 phase-3의 재처리 멱등성 항목에 있다.

**트레이드오프** — 폴백을 아예 저장하지 않는 대안은 PDF를 받지 못한 논문을 검색에서 없앤다. 순위 규칙은 "낮은 순위
결과는 기존 결과를 이기지 못한다"로 설명되지만, 실제로 낮은 순위로 되돌려야 하는 경우를 위해 `--force` 경로(worker CLI,
requeue 스크립트, job payload)를 따로 유지해야 한다.

**eval 영향** — `tests/unit/test_prepare_pipeline.py`의 `test_lower_ranked_source_does_not_overwrite_existing_fulltext`,
`test_force_overwrites_with_lower_ranked_source`, 통합 테스트 `tests/integration/test_prepare_idempotency_pg.py`의
`test_re_prepare_is_idempotent_and_never_downgrades_without_force`가 규칙을 고정한다. 재처리 뒤에도 청크 id가 유지되어야
평가 질의셋의 정답 청크 id(`relevant_chunk_ids`)가 유효하다.

**알려진 한계** — 순위는 source 종류만 본다. 같은 `pdf` source 안에서 새 파싱 결과가 더 나쁜 경우는 막지 못한다.

**트러블슈팅** — 다운로드 실패 한 번으로 본문과 임베딩이 사라짐

- 증상: PDF 다운로드가 일시적으로 실패한 논문을 다시 prepare하면 본문이 초록으로 바뀌고 그 논문의 청크 임베딩이
  사라졌다.
- 원인: 초록 폴백 결과가 정상 파싱 결과와 같은 저장 경로를 탔고, 청크 교체의 `DELETE FROM paper_chunks`가
  `paper_embeddings`로 cascade됐다.
- 확인 방법: `src/pipeline/prepare_papers.py`의 저장 분기가 source를 구분하지 않는 것과 스키마의 cascade 제약을 코드에서
  확인했다.
- 해결: 파싱된 본문이 있으면 폴백을 저장하지 않게 했고(dc0981d), source 순위·`content_hash`·`--force`로 일반화했다
  (f229c59). `test_lower_ranked_source_does_not_overwrite_existing_fulltext`와
  `test_re_prepare_is_idempotent_and_never_downgrades_without_force`가 통과한다.
- 재발 방지: 단위 테스트는 CI python 잡, 통합 테스트는 pgvector 서비스를 띄우는 integration 잡에서 돈다. 낮은 순위로
  덮어쓰려면 `--force`를 명시해야 한다.
