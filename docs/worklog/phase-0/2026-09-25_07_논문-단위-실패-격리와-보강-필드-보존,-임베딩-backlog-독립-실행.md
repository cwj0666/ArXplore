---
title: 논문 단위 실패 격리와 보강 필드 보존, 임베딩 backlog 독립 실행
date: 2026-09-25
area: [pipeline]
decision: 날짜 잡 안에서 논문 하나의 예외가 잡 전체를 실패시키지 않게 하고, 재처리가 보강 필드를 지우지 않게 하며, 임베딩 backlog를 prepare 성공 여부와 무관하게 돌린다
---

**결정과 근거** — 감사에서 prepare 파이프라인의 세 결함을 찾았다. (1) 날짜 잡이 논문을 순회하다 한 건의 예외로 전체가
실패했다. (2) 재처리 때 `save_paper`가 보강 필드를 덮었다. `categories`는 빈 JSONB 배열 `[]`로 들어오는데 `COALESCE`는
`[]`를 NULL로 보지 않아 기존 값이 빈 배열로 바뀌었다. (3) prepare-worker의 임베딩 backlog 처리가 prepare 성공 뒤에만
실행됐다. 두 개의 이른 return 때문에 prepare가 실패하거나 처리할 잡이 없으면 밀린 임베딩이 계속 쌓였다. 논문 단위로
예외를 잡아 기록하고 계속 진행하며, 보강 필드는 충돌 시 기존 값을 보존하고, backlog는 prepare 결과와 독립으로 돌게
했다(dc0981d).

**트레이드오프** — 논문 단위 격리는 "일부만 성공한 잡"이라는 상태를 만든다. 처음에는 이를 완료로 처리했으나 리뷰에서
실패한 논문이 재시도되지 않는다는 지적을 받아, 실패가 섞인 잡은 backoff 후 재시도하고 이미 성공한 논문은 unchanged로
건너뛰게 바꿨다(phase-3 재처리 멱등성 항목). backlog를 매 run 돌리면 prepare가 없는 run에도 임베딩 API를 부르므로 CLI
기본 상한(400)을 둔다.

**eval 영향** — `test_prepare_pipeline.py`의 `test_run_prepare_papers_isolates_per_paper_failures`,
`test_run_prepare_papers_all_failed`, `test_paper_repository_sql.py`의 `test_save_paper_preserves_enrichment_on_conflict`,
`test_prepare_worker.py`의 `test_backlog_runs_without_prepare_success`, `test_backlog_runs_after_failed_prepare`,
`test_cli_defaults_embed_backlog_to_400_and_force_off`. 로컬 코퍼스에서는 청크 15,897개 중 references 1,772개를 뺀
14,125개가 모두 임베딩되어, 검색 평가 시점에 backlog가 남지 않았다.

**알려진 한계** — 논문 단위 실패 사유는 잡 결과 집계와 로그에만 남고, 논문별 실패 이력 테이블은 없다.

**트러블슈팅** — 논문 한 건의 예외로 날짜 잡 전체가 실패

- 증상: 한 날짜의 논문 중 하나만 파싱이나 저장에서 예외를 내도 그 날짜의 나머지 논문이 처리되지 않고 잡이 실패했다.
- 원인: `run_prepare_papers`의 논문 루프에 논문 단위 예외 처리가 없어 첫 예외가 날짜 잡까지 전파됐다.
- 확인 방법: 루프 구조를 읽어 확인했고, 한 논문에서만 예외를 내는 가짜 파서로 재현하는 테스트를 만들었다.
- 해결: 논문 단위로 예외를 잡아 결과 집계에 실패로 세고 다음 논문으로 넘어간다(dc0981d).
  `test_run_prepare_papers_isolates_per_paper_failures`가 통과한다. 실패가 섞인 잡의 재시도는 f229c59에서 더했다.
- 재발 방지: 전부 실패(`test_run_prepare_papers_all_failed`), 빈 날짜(`test_run_prepare_papers_empty_date_is_success`),
  일부 실패(`test_consume_queue_retries_job_on_partial_failure`)를 각각 테스트로 고정했다.
