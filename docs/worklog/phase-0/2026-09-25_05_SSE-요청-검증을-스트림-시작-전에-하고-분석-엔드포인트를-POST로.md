---
title: SSE 요청 검증을 스트림 시작 전에 하고 분석 엔드포인트를 POST로
date: 2026-09-25
area: [backend]
decision: SSE 엔드포인트의 입력·권한 검증을 제너레이터 밖으로 옮겨 실제 4xx 상태 코드를 돌려주고, 부수 효과가 있는 paper_analyze를 POST 전용으로 바꾼다
---

**결정과 근거** — 에이전트·상세 챗 SSE 뷰는 검증을 스트림 제너레이터 안에서 했다. 응답 헤더가 이미 200으로 나간 뒤라
인증 실패(401)나 잘못된 입력(400)이 HTTP 200 + `error` 이벤트로 바뀌었고, 클라이언트는 상태 코드로 오류를 구분할 수 없었다.
`backend/papers/api_views.py`에서 검증을 먼저 끝내고 통과한 요청만 `StreamingHttpResponse`로 넘기게 했다(dc0981d).
LLM을 호출하고 결과를 캐시하는 `paper_analyze`는 GET이었으므로 링크 미리보기나 크롤러도 생성을 일으킬 수 있었다. POST
전용으로 바꾸고 CSRF 헤더를 요구한다.

**트레이드오프** — 검증 로직이 스트림 경로와 비스트림 경로에서 한 번씩 불리도록 뷰를 나눠야 했다. 스트림 도중의 오류는
여전히 `error` 이벤트로만 알릴 수 있으므로, 이벤트 계약(`chunk`* → `citations` → `[DONE]`, 오류 시 `error` → `[DONE]`)을
`docs/architecture/AGENTS.md`에 적었다.

**eval 영향** — `tests/unit/test_api_views.py`의 `test_empty_message_returns_400`, `test_invalid_body_returns_400`,
`test_unknown_paper_returns_404`, `test_missing_server_api_key_returns_503`(로그인 제거 뒤 키 부재는 503),
`test_get_is_not_allowed`, `test_post_calls_analysis`. 생성 평가의 입력 거부 케이스 4건(`rejected_as_expected`)이 이 검증
경로를 전제로 한다.

**알려진 한계** — 스트림이 시작된 뒤의 실패는 상태 코드로 드러나지 않는다. 클라이언트가 `[DONE]` 없이 끊긴 스트림을
오류로 다루는 부분은 phase-3 리뷰에서 보강했다.

**트러블슈팅** — 잘못된 요청이 HTTP 200으로 응답됨

- 증상: 빈 메시지나 인증 없는 요청에도 SSE 엔드포인트가 HTTP 200을 돌려주고 본문에 `error` 이벤트만 실었다.
- 원인: 검증 코드가 `StreamingHttpResponse`에 넘긴 제너레이터 안에 있어, 첫 이벤트를 만들 때 이미 200 헤더가 확정됐다.
- 확인 방법: 뷰의 호출 순서를 따라가 검증이 제너레이터 안에 있는 것을 확인했다. `test_api_views.py`는 `RequestFactory`로
  빈 메시지를 보내 응답 상태 코드를 확인한다.
- 해결: 검증을 스트림 생성 전으로 옮겼다(dc0981d). `test_empty_message_returns_400`, `test_invalid_body_returns_400`이
  통과한다.
- 재발 방지: SSE 뷰마다 4xx·503 경로와 GET 거부를 `test_api_views.py`가 고정한다.
