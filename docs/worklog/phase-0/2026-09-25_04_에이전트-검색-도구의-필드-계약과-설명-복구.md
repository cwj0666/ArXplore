---
title: 에이전트 검색 도구의 필드 계약과 설명 복구
date: 2026-09-25
area: [agent]
decision: 에이전트 검색 도구가 retriever 결과의 paper_title·context_text·section_title을 읽게 고치고, 도구 docstring을 실제 검색 방식대로 쓰며, 줄바꿈 리터럴을 고친다
---

**결정과 근거** — retriever는 논문 제목을 `paper_title`로 돌려주는데 에이전트 도구는 `title`을 읽어 모든 hit이 "제목 없음"으로
LLM에 전달됐다. 도구 docstring은 벡터 DB 검색이라고 적었지만 실제로는 PostgreSQL 전문 검색을 불렀고, 트렌딩 도구는
`"\\n".join`으로 줄바꿈 대신 백슬래시-n 문자열을 넣었다. docstring은 LLM이 도구를 고를 때 읽는 입력이므로 실제 동작과
같아야 한다. `src/core/agent/tools.py`의 포매터가 `paper_title`(없으면 `title`), `context_text`(없으면 `chunk_text`),
`section_title`, `chunk_id`, URL(`pdf_url` 다음 abs 링크)을 읽게 했다(dc0981d). docstring은 phase-2에서 hybrid 검색으로
바꿀 때 다시 맞췄다.

**트레이드오프** — `title`로의 폴백을 남겨 두 키 이름을 모두 받는다. 필드 계약을 한 곳으로 모으는 대안(typed dict)은
범위가 커서 미뤘고, CLAUDE.md의 Retrieval 결과 shape 계약과 테스트로 대신한다.

**eval 영향** — `tests/unit/test_agent_tools.py`의 `test_formatter_uses_retriever_paper_title`,
`test_formatter_includes_every_citation_field`, `test_trending_tool_joins_lines_with_real_newline`,
`test_search_tool_docstring_describes_hybrid_search`. 도구 출력의 제목은 이후 인용 검증과 행동 지표
`mentions_required_ids`(인용된 제목이 답변에 나오는지)의 입력이 된다.

**알려진 한계** — 포매터가 받는 dict의 키 이름은 여전히 문자열 계약이다. 새 필드를 retriever에 더할 때 도구 쪽 테스트를
함께 고쳐야 한다.

**트러블슈팅** — 에이전트가 보는 모든 검색 결과가 "제목 없음"

- 증상: 에이전트 답변의 근거 목록에서 모든 논문 제목이 "제목 없음"으로 나왔다.
- 원인: retriever 결과 키는 `paper_title`인데 도구 포매터가 `title`을 읽었다.
- 확인 방법: retriever 반환 dict와 포매터가 읽는 키를 대조했다. `test_formatter_uses_retriever_paper_title`가 retriever와 같은
  키 이름의 픽스처로 이 경우를 재현한다.
- 해결: 포매터가 `paper_title`을 우선 읽고 `title`로 폴백한다(dc0981d). 같은 커밋에서 docstring과 줄바꿈 리터럴도 고쳤다.
  `test_agent_tools.py`의 포매터 테스트 9개가 통과한다.
- 재발 방지: 포매터 테스트가 retriever 반환 형태의 픽스처를 쓰고, CLAUDE.md의 Architectural Contracts에 Retrieval 결과
  shape를 적어 두었다.
