title: 프론트엔드 React 19·데이터 라우터 이식과 G6 동등성
date: 2026-09-29
area: [frontend]
decision: 같은 화면·문구·URL 규칙으로 `v2/frontend`를 새로 짜고(React 19, React Router 7 데이터 라우터와 lazy 라우트, TanStack Query, CSS Modules) G6 11개 화면이 텍스트·ARIA·픽셀까지 같음을 확인한 뒤 F19·F27~F29를 얹는다. 최초 로드 번들이 커져도 라우트 단위 오류 경계와 lazy 로딩 때문에 데이터 라우터를 유지하고, API 타입은 FastAPI OpenAPI에서 생성한다
---

**결정과 근거** — 옛 프론트는 React 18과 react-router-dom 6 위에 페이지별 전역 CSS를 썼고, TanStack Query는 `App.tsx` 한
곳에서만 썼다. 화면과 문구는 그대로 두고 구조를 새로 짰다(ae59715).
- `app/`은 데이터 라우터(`createBrowserRouter`)와 lazy 페이지 라우트, bootstrap 게이트, provider, 오류 경계를 둔다.
  `pages/`는 기능을 조립만 하고, `features/`는 목록, 논문 상세, 공용 채팅 조각, 상세 챗, 어시스턴트로 나눈다. 두 채팅은
  `useChatStream` 훅 하나를 쓰고 화면마다 다른 안내 문구를 옵션으로 넘긴다.
- 목록과 상세는 TanStack Query 쿼리, 개요와 요약은 취소할 수 있는 mutation이다.
- 스타일은 기존 토큰 위의 CSS Modules다. 페이지 초기화 규칙은 명시도 0인 `:where()`로 써서 모듈 순서가 cascade를 바꾸지
  않게 했고, 옛 cascade가 덮어쓰던 값은 실제 적용값으로 적었다.
- 도구: TypeScript 6.0 strict, ESLint 10 flat config(typescript-eslint, react-hooks, jsx-a11y, 주석 금지 규칙), Prettier,
  Vitest와 Testing Library. TypeScript는 typescript-eslint 8.71이 `<6.1`만 지원해 6.0에 둔다(01번 항목).
- 옛 미니 마크다운 렌더러와 도달하지 않는 비스트리밍 채팅 폴백도 이식 단계에서는 동등성을 위해 그대로 옮겼다.

G6 동등성
- 옛 골든(87fd591): 옛 프론트 빌드를 골든 DB 사본 위 Django가 서빙하고, 가짜 OpenAI 서버가 개요·핵심 포인트·요약·상세
  챗·에이전트에 답한다. Playwright 1.63.0(Chromium headless, 1440×900, ko-KR, Asia/Seoul, 모션 줄임)으로 11개 화면의 PNG,
  innerText, ARIA 스냅샷을 캡처했고 세 번 캡처가 바이트까지 같았다.
- v2 캡처(572666d): v2 빌드를 `vite preview`로 띄우고 API는 옛 Django 백엔드로 프록시한다. 클래스 이름에 기대던 선택자 두
  개만 역할·id 기반으로 바꿨다. innerText와 ARIA는 바이트가 같아야 하고 PNG는 달라진 픽셀이 0이어야 한다. 이식 시점에
  11개 화면이 모두 같았다.

수정(`g6_ui.v2.diff.md`)
- F19(015b899): 검색어가 있는데 결과가 0건이면 "검색 결과가 없습니다."를 보인다. `list_no_results`의 문구 한 줄만 바뀌고
  PNG는 그 영역 1,674픽셀만 다르다.
- F27(b45ef00): 클라이언트 `/papers/` 경로가 쿼리를 버리고 `/`로 갔다. 이제 원래 search와 hash를 붙인다.
  `/papers/?q=diffusion`이 `/?q=diffusion`에 도착한다. G6은 `/papers/`를 방문하지 않아 차이가 없다.
- F28(afef933): 백엔드가 내지 않는 조건(404 + JSON 오류 없음)에서만 타던 상세 챗 비스트리밍 폴백을 지웠다. 백엔드 엔드포인트는
  다른 클라이언트를 위해 남긴다.
- F29 접근성(538befa): 논문 카드는 `role=link` 카드 안에 PDF 링크가 든 중첩 링크였다. 이제 카드는 `article`이고 PDF 링크와
  실제 상세 링크가 나란히 있으며, 상세 링크의 `::before`가 카드 전체를 덮고 포커스 링은 `:has()`로 카드에 그린다. 상세 챗
  패널은 열면 입력창으로, Esc나 닫기로 닫으면 여는 버튼으로 포커스를 옮긴다. 어시스턴트 입력창과 PDF 분할창 닫기 버튼에
  이름을 붙였다. G6에서는 화면 4개의 ARIA 스냅샷만 바뀌고 innerText와 PNG는 같다.
- F29 마크다운(4a05e11): 손으로 쓴 마크다운→HTML 변환과 innerHTML 대입을 react-markdown 10, remark-gfm, remark-breaks,
  rehype-sanitize로 바꿨다. 표, 기울임, 취소선, 인용, 중첩·할 일 목록, 맨 URL이 렌더된다. 링크 규칙(http(s)만, 새 탭, arXiv
  abs·pdf 링크는 내부 논문 페이지로)은 그대로고, 원시 HTML은 지우고 이미지는 대체 텍스트만 보인다. G6 11개 화면은 전후가
  같다.
- OpenAPI 생성 타입(c9c890b): `uv run arxplore openapi` 출력을 `v2/frontend/openapi.json`으로 커밋해 프론트 빌드에 Python이
  필요 없게 했다. `npm run generate:api`가 openapi-typescript 7.13으로 `src/shared/api/schema.d.ts`를 만들고, `types.ts`는
  operationId와 컴포넌트 스키마로 이름을 붙인다. `npm run lint`는 생성 타입이 `openapi.json`과 맞는지, `npm run check:api`는
  백엔드로 스키마를 다시 뽑아 커밋한 파일과 같은지 본다.

**트레이드오프** — 데이터 라우터와 라우트 단위 코드 분할을 쓰면 최초 로드 번들이 옛 단일 번들보다 커진다. 상세와
어시스턴트 쪽에는 react-markdown 계열도 더해졌다. 선언형 라우터로 바꾸면 번들을 줄일 수 있지만 라우트 단위 오류 경계와
lazy 로딩을 잃으므로, 검토에서 데이터 라우터를 유지하기로 했다.
- F29 마크다운: 빈 줄 없는 줄바꿈은 이제 한 문단 안의 `<br>`라 옛 화면의 줄 사이 문단 간격(상세 챗 8px, 어시스턴트 10px)이
  없다. `####` 이상도 h5로 그리고, 원시 HTML은 이스케이프해 보이는 대신 태그를 지운다. 코드 블록 innerText 끝에 줄바꿈이
  하나 붙는다.
- F29 카드: 탭 순서가 카드 → PDF 링크에서 PDF 링크 → 상세 링크로 바뀌고, Space 키로는 이동하지 않는다(Enter만). Ctrl·Cmd
  클릭과 가운데 클릭은 브라우저 기본 동작대로 새 탭을 연다.
- OpenAPI 타입: 커밋한 스키마가 백엔드와 어긋날 수 있어 검사 두 개를 둔다. `check:api`는 uv와 v2 프로젝트가 있어야 돈다.
  openapi-typescript가 typescript `^5`를 peer로 선언해 npm override로 TypeScript 6.0에 맞췄다.

**eval 영향** — 새 측정 지점은 다음과 같다.
- G6 v2 변형 `tests/golden/data/g6_ui.v2/`(바뀐 파일만)와 `g6_ui.v2.diff.md`. 비교는
  `.venv/bin/python -m pytest tests/golden/ui/test_g6_ui_v2.py`
- Vitest 테스트 파일 13개(`v2/frontend/src/**/*.test.ts(x)`). 예: `MarkdownContent.test.tsx`(XSS 입력: script, 이벤트
  핸들러, javascript:·data: 링크, 엔티티 인코딩, 원시 HTML, SVG), `PapersAliasRedirect.test.tsx`(F27),
  `PaperChatPanel.test.tsx`(포커스·Esc)
- `npm run lint`(ESLint, Prettier, 생성 타입 대조), `npm run typecheck`, `npm run build`, `npm run check:api`

**알려진 한계** — G6 v2는 v2 프론트를 옛 Django 백엔드에 붙여 잰다. v2 프론트와 FastAPI의 조합은 G5 계약과 OpenAPI
생성 타입으로만 맞춘다.
- G6은 11개 화면만 본다. 로딩, 오류, 429 같은 그 밖의 상태는 Vitest가 DOM 수준에서만 본다.
- G6의 두 답변은 문단·목록과 굵은 글씨 안 링크만 쓴다. 표·인용 같은 새 마크다운 문법은 단위 테스트로만 확인한다.
- 번들 크기 비교 수치는 결과 파일로 남기지 않았다.

**트러블슈팅** — 해당 없음
