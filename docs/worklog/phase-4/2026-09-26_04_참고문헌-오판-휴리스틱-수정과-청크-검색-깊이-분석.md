---
title: 참고문헌 오판 휴리스틱 수정과 청크 검색 깊이 분석
date: 2026-09-26
area: [retrieval, eval]
decision: 청크 합성 질의의 낮은 chunk hit@5(hybrid 0.533)는 결과 수가 아니라 lexical 필터의 참고문헌 오판과 논문 다양성 보정 때문이므로, `_looks_reference_like_text`를 "줄 머리 `[n]` 항목 3개 이상"과 "인용 표지·학회명 + 연도 2개 이상" 기준으로 바꾸고 다양성 보정은 multi_paper 손실 때문에 유지한다
---

**결정과 근거** — 에이전트 llm_synth 15건에서 정답 청크가 도구 결과에 없던 원인을 검색 평가(`20260925-225658.csv`)와
답변 파일로 가른 결과다. (1) hybrid에서 정답 청크가 6~10위에 있는 질의는 없어(chunk hit@5 = hit@10 = 0.533) 도구 결과 수
5개를 늘려도 얻는 게 없다. (2) ablation 질의별 비교에서 `lexical_nofilter`는 lexical이 놓친 cs-12667·cs-15375·cs-472를
찾고(chunk hit@5 0.467 → 0.667, 논문 단위 hit@10도 0.643 → 0.675), `hybrid_nodiv`는 cs-12667·cs-7154를 찾는다(0.533 → 0.667).
(3) 필터에 걸린 정답 청크는 "RF-DETR-2XL [2] … RF-DETR-M [2] … YOLO11-M [1]" 같은 결과 표와 인용이 많은 서론이었다.
`_looks_reference_like_text`가 `[n]` 표지 3개만으로 참고문헌으로 판정했기 때문이다. 저장된 발췌문 636개(중복 제거)에 같은
함수를 돌리니 16개가 걸렸고 실제 참고문헌은 3개, 나머지 13개는 연도가 0개인 본문이었다.

휴리스틱을 바꿨다: 공백 정규화 기준 앞 1,200자에서 줄 머리가 `[n]`으로 시작하는 줄이 3개 이상이면 번호 참고문헌 목록으로
보고, 문장 안의 인용 표지는 연도가 2개 이상 함께 있을 때만 센다(학회명 규칙과 저자 목록 규칙은 그대로). 같은 발췌문 636개에서
걸리는 것은 실제 참고문헌 3개뿐이다. 이 함수는 lexical 필터와 vector 재정렬 감점(-0.14)이 함께 쓰므로 둘 다 바뀐다.

다양성 보정(`_apply_paper_diversity`, 논문당 2청크)은 유지한다. `*_nodiv`는 청크 단위를 올리지만 multi_paper hit@10이 0.667 →
0.500, manual 0.558 → 0.524, 전체 hit@10 0.817 → 0.807로 내려간다. 한 논문 안의 여러 청크가 필요한 질문과 여러 논문을 찾는
질문이 서로 반대 방향이라 어느 한쪽을 고르지 않았다.

**트레이드오프** — 연도 없는 번호 참고문헌이 한 줄로 이어진 텍스트(파서가 줄바꿈을 잃은 경우)는 이제 필터를 통과한다.
1차 방어는 파서의 `content_role=references`와 섹션 제목 판정이고 휴리스틱은 보조라서 받아들였다. 필터가 걸러 내던 noise@10은
0.002(lexical_nofilter 기준)라 잃는 것이 작다. 실제 효과는 로컬 DB가 꺼져 있어 재측정하지 않았고, 저장된 발췌문에 대한 오프라인
검증만 했다. 에이전트가 도구에 넘기는 질의가 원문과 달라 검색 평가와 결과가 어긋나는 문제(cs-11328: 검색 평가는 4위, 에이전트는
이웃 청크만 받음)는 남겨 두었다.

**eval 영향** — `tests/unit/test_retrieval_filters.py`: 줄 머리 항목 3개(들여쓰기 포함)는 잡고, 문장 안 인용 3개·인용 많은
서론·인용 표지가 든 결과 표·항목 1개 + 인용 2개는 통과시키는 케이스를 추가했다. 1,200자 창 테스트는 항목 형식으로 바꿨다. 재측정
지점: llm_synth 부분집합의 chunk hit@5(hybrid 0.533, lexical 0.467), 전체 noise@10(0.000), lexical hit@10(0.643).

**알려진 한계** — cs-11002·cs-2121·cs-3005는 어느 방식·ablation으로도 정답 청크를 못 찾는다(질의가 논문 문맥 없이는 특정되지
않거나 부록 청크). 청크 단위 지표는 15건이라 1건이 0.067을 움직인다. 다양성 보정의 논문당 상한 2를 3으로 올리는 중간안은
측정하지 않았다.

**트러블슈팅** — 인용 표지가 든 결과 표 청크가 참고문헌으로 걸러짐

- 증상: cs-12667("GTX 1070 Ti에서 TAPe+ML v3 프레임당 추론 시간")의 정답 청크가 lexical·hybrid 상위 10개에 없고,
  `lexical_nofilter`에서는 5위 안에 있었다.
- 원인: 정답 청크의 표 행에 "[2]", "[2]", "[1]" 인용 표지가 있어 `_looks_reference_like_text`의 "표지 3개 이상" 규칙에 걸렸다.
- 확인 방법: `eval/results/20260925-225658.csv`에서 방식별 `chunk_hit@5`를 질의별로 비교하고, `answers_run2.jsonl`의 상세 챗
  발췌문에서 해당 표를 확인했다. 저장된 발췌문 636개에 함수를 돌려 오판 13개를 셌다.
- 해결: 줄 머리 항목 기준으로 바꿨다. 같은 636개에서 오판 0개, 실제 참고문헌 3개 유지. 단위 테스트 858건 통과. 지표 전후는
  재측정 뒤 덧붙인다.
- 재발 방지: `test_not_detected`의 `citation-heavy-intro`, `table-rows-with-cites` 케이스.
