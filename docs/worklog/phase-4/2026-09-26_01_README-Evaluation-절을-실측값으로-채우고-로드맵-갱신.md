**결정과 근거** — 0c84671로 결과 파일이 커밋된 뒤에도 README는 "검색 품질은 아직 측정하지 않았습니다"와 "측정 예정" 표를 그대로
두고 있었다. 문서와 실측이 어긋난 상태를 닫기 위해 README 붙여넣기용 표를 결과 파일에서 옮기고, 각 표 위에 코퍼스 규모
(275편·청크 15,897·임베딩 14,125·본문 source pdf 275), 질의 수(146개 중 채점 115개), 답변 수(243개), 모델(답변 gpt-4o·판정
gpt-5-mini), 결과 파일 이름과 측정 시점 커밋(5f9c4cd, bcdc84b)을 적었다. 값은 `eval/results/20260925-225658.md`와
`eval/results/generation_20260925-233840.md`의 표에서만 가져왔고 반올림하지 않았다.

표 아래에는 worklog 07·10에 적은 해석 중 README 독자에게 필요한 것만 옮겼다: hybrid가 vector를 넘지 못했는데 기본값을 유지한
이유, 표준 RRF ablation이 hit@1과 hit@10을 맞바꾸는 점, 가장 약한 부분집합(query_form, 한국어 lexical), 생성 평가에서 낮은
부분집합(에이전트 llm_synth faithfulness 0.688, evidence_location answer_relevancy), 단일 실행이라 분산을 모른다는 점.
행동 지표는 모드별로 다른 값(거절 정확도 에이전트 0.933·상세 챗 0.833)을 하나로 뭉뚱그리지 않고 따로 적었다.

**트레이드오프** — README에 수치를 넣으면 평가를 다시 돌릴 때마다 README도 같이 고쳐야 한다. 대신 결과 파일 이름과 커밋 해시를
같이 적어 어느 실행의 값인지 추적할 수 있게 했다. 질의셋 설명은 "30~50개"라는 계획 수치를 지우고 실제 구성(known-item·청크 합성·
8개 관점 수작업 74개)으로 바꿨다. 본문 source가 모두 pypdf라는 사실은 숨기지 않고 표 위와 로드맵에 적었다. HURIDOCS 파싱
결과에서의 재측정은 미뤘다.

**eval 영향** — 새 측정 지점은 없다. README의 두 표가 `eval/results/*.md`의 "README 붙여넣기용" 표와 같은 모양이므로, 다음
실행 결과는 그 표를 그대로 바꿔 넣으면 된다.

**알려진 한계** — README 수치와 결과 파일이 어긋나도 자동으로 잡는 검사는 없다. `scripts/worklog.py check`는 worklog만 검사한다.

**트러블슈팅** — 해당 없음
