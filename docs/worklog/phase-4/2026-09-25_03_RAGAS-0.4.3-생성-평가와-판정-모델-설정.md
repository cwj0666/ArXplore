---
title: RAGAS 0.4.3 생성 평가와 판정 모델 설정
date: 2026-09-25
area: [eval, tooling]
decision: 에이전트와 상세 챗의 답변과 LLM에 넘긴 발췌문을 모아 RAGAS 0.4.3(판정 gpt-5-mini)으로 faithfulness·answer_relevancy·context_precision·context_recall을 재고, 계산 조건이 안 되는 지표는 n/a로 남긴다
---

**결정과 근거** — 검색 지표만으로는 답변이 발췌문에 근거하는지 알 수 없어 생성 평가를 더했다(875287a). langchain 1.x와 함께
설치되는 RAGAS 0.4.3을 쓰고, 판정 모델은 `gpt-5-mini`, 임베딩은 `text-embedding-3-small`이다. RAGAS는 gpt-5 계열에서
temperature를 1.0으로 고정하므로 넘기지 않고, 추론 토큰이 출력 한도를 같이 쓰므로 판정 출력 한도를 넉넉히 준다. 한국어
질의에는 지표 프롬프트의 few-shot 예시를 한국어로 adapt한다. 지표 계산 조건: faithfulness는 발췌문이 있을 때,
answer_relevancy는 답변이 있을 때, context_precision은 `reference_answer`나 정답 청크 본문이 있을 때, context_recall은
`reference_answer`가 있을 때만 계산하고 나머지는 n/a다. 에이전트가 LLM에 넘긴 발췌문은 도구 모듈의 `retrieve_contexts`를
기록용 래퍼로 잠시 바꿔 모은다.

**트레이드오프** — LLM 판정 점수는 판정 모델과 프롬프트에 따라 달라지므로 같은 판정 모델·같은 답변 파일로 잰 값끼리 상대
비교에만 쓴다. 판정 temperature가 1.0이라 같은 입력도 재실행마다 점수가 흔들린다. 질의셋에 `reference_answer`를 쓰지 않아
context_recall은 이번 실행에서 모두 n/a다. 답변 수집과 채점을 나눠 저장된 답변만 다시 채점할 수 있게 했다(판정 비용만 든다).

**eval 영향** — `tests/unit/test_eval_generation.py`(43개): `test_capture_records_texts_the_tool_passes_to_the_llm_and_restores`,
`test_gold_chunks_feed_context_precision_but_not_recall`, `test_no_reference_skips_precision_and_recall`,
`test_nan_is_not_averaged`, `test_missing_key_exits_without_writing`. 결과는 `eval/results/generation_<timestamp>.md`와 CSV로
남고 머리에 답변 모델·판정 모델·답변 파일 sha256을 적는다.

**알려진 한계** — 발췌문 기록 래퍼는 모듈 전역 함수를 바꾸므로 답변 수집을 병렬로 돌릴 수 없다(순차 전용). context_precision은
정답 청크가 있는 질의(에이전트 14~15건, 상세 챗 15건)로만 계산되어 표본이 작다.

**트러블슈팅** — 해당 없음
