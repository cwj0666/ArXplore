---
title: query_form 정답 라벨 오류와 주제 집합 자리표시자
date: 2026-09-26
area: [eval]
decision: query_form 관점의 낮은 hit@10(0.167~0.333)은 검색이 아니라 정답 라벨 오류였으므로, 주제를 묻는 질의 10건의 정답을 "조건에 맞는 논문 전부"로 두는 집합 자리표시자(all_matches, title_keywords OR 목록, exclude_title_keywords)를 카탈로그와 attach-ids에 도입한다
---

**결정과 근거** — 20260925-225658 결과에서 query_form 12건 중 제목 전체·일부 2건만 맞고 10건은 세 방식 모두 0이었다.
결과 CSV의 `retrieved_arxiv_ids`와 질의셋의 정답 id를 제목으로 대조하니 검색 결과는 주제에 맞고 정답 라벨이 틀려 있었다.
자리표시자를 제목 키워드 하나로 채우는 규칙이 원인이다: "4비트 양자화" 질의의 정답 `0000.0000q`(`Quantiz`)는 벡터 양자화
토크나이저 논문(StableVQ)에, 긴 문맥 질의의 `0000.0000e`(`Context`)는 로봇 in-context 학습 논문에, MoE 라우팅 질의의
`0000.0000d`(`Expert`)는 장면 텍스트 인식 MoE 논문에 붙었고, 실제 상위 결과는 HyQuant·VC-Attention, SpectralShift·KV cache
논문, IntBMoE·Expert-Space Exploration이었다. "diffusion" 한 단어 질의는 확산 모델 논문 4편을 상위에 냈지만 정답은
Flash-dLLM 한 편이라 0점이었다.

주제 질의는 특정 논문이 아니라 주제에 속한 논문 아무거나 찾으면 성공이므로, 정답을 집합으로 둔다. `placeholders.json`에
`all_matches: true`, `title_keywords`(OR 목록), `exclude_title_keywords`를 추가하고 집합 자리표시자 `0000.0000r`(Diffusion),
`s`(강화학습), `t`(비디오 생성·월드 모델), `u`(양자화, 벡터 양자화 토크나이저 제외), `v`(MoE), `w`(긴 문맥, in-context 제외),
`x`(RAG·검색)를 정의했다. `candidate_sql`은 OR·NOT ILIKE를 만들고 집합은 최대 50편을 가져오며, `choose_distinct`는 집합
자리표시자에 후보 전부를 붙이고 다른 자리표시자가 고른 논문도 빼지 않는다. `fill_placeholders`는 리스트 안의 집합
자리표시자를 모든 id로 펼치고 문자열 안에서는 첫 논문을 쓴다. `query_form.jsonl`의 10건이 집합 자리표시자를 가리킨다.

**트레이드오프** — 집합 정답은 hit@k를 "주제에 맞는 논문이 상위 k에 있는가"로 바꾼다. 한 편만 정답일 때보다 관대하고,
recall@10은 집합 크기에 따라 낮게 나오므로 query_form 부분집합에서는 hit@k만 읽는다. 제목 키워드 목록은 손으로 고른 것이라
제목에 키워드가 없는 주제 논문은 집합에서 빠진다. 대안으로 초록 키워드 매칭이나 사람이 275편을 직접 라벨링하는 방법이 있지만,
코퍼스가 바뀔 때마다 다시 해야 해서 택하지 않았다. 지표 계산과 다른 관점의 라벨은 바꾸지 않았다.

**eval 영향** — `tests/unit/test_eval_cases.py`에 집합 자리표시자 펼치기, `choose_distinct`의 집합 처리, `candidate_sql`의
OR·NOT 절, 조건 파일 검증, query_form 10건이 집합 자리표시자를 쓰는지 확인하는 테스트를 더했다. 재측정은 `--attach-ids
--write`로 질의셋을 다시 만든 뒤 `eval_retrieval.py`를 돌려야 하며, 이 항목 시점에는 로컬 DB가 꺼져 있어 아직 하지 않았다.
README Evaluation 절의 query_form 수치는 라벨 오류가 있는 첫 실측 값 그대로 두고 문장으로 사정을 적었다.

**알려진 한계** — 집합이 비면 자리표시자가 남아 케이스가 빠진다(`attach_catalogue`가 목록에 보고). 제목 키워드가 우연히
맞는 무관한 논문이 집합에 섞일 수 있고, 이를 거르는 검사는 `--attach-ids` 출력에서 사람이 훑어보는 것뿐이다.
`qf-single-word-ko`("강화학습")는 여전히 `clarify` 기대이고 정답 집합은 검색 평가에만 쓴다.

**트러블슈팅** — 검색이 맞는데 hit@10이 0으로 나옴

- 증상: query_form 관점 hit@10이 lexical 0.333, vector 0.250, hybrid 0.167인데 상위 결과 제목은 질의 주제와 맞았다.
- 원인: `--attach-ids`가 자리표시자마다 제목 ILIKE 첫 후보 하나만 정답으로 붙였고, 키워드가 주제를 특정하지 못했다(`Quantiz`,
  `Context`, `Expert`).
- 확인 방법: `eval/results/20260925-225658.csv`의 hybrid 행에서 `retrieved_arxiv_ids`를 꺼내 `eval/queries.jsonl`·답변
  파일의 제목과 대조했다(DB 없이 저장된 파일만 사용).
- 해결: 집합 자리표시자와 OR·제외 키워드를 도입하고 query_form 10건의 정답을 집합으로 바꿨다. 단위 테스트 853건 통과.
  수치 검증은 재측정 뒤에 이 항목에 덧붙인다.
- 재발 방지: `test_topic_cases_use_set_placeholders`가 주제 질의가 단일 자리표시자로 되돌아가는 것을 막는다. `--attach-ids`
  출력이 집합의 포함 논문을 모두 나열해 사람이 확인할 수 있다.
