**결정과 근거** — 5f9c4cd 시점 로컬 코퍼스(275편)에서 146개 질의(LLM 생성 72 = known_item 57 + chunk_synth 15, 수작업 케이스
74)를 돌렸고 정답 논문이 있는 115개를 k=10으로 채점했다(`eval/results/20260925-225658.md`). 논문 단위 결과:

| 방식 | hit@1 | hit@10 | MRR@10 | p50 / p95 (ms) |
|---|---|---|---|---|
| lexical | 0.539 | 0.643 | 0.573 | 202 / 427 |
| vector | 0.704 | 0.826 | 0.741 | 173 / 243 |
| hybrid | 0.704 | 0.817 | 0.737 | 483 / 821 |

hybrid는 vector를 넘지 못했다. 부분집합에서는 영어 질의의 lexical hit@1(0.727)이 vector
(0.709)보다 높고, known_item은 vector·hybrid 모두 hit@10 1.000이다. 기본값을 vector로 바꾸면 임베딩 키가 없을 때의 폴백
경로(lexical)와 영어 정확 일치 신호를 따로 관리해야 하므로, 기본값은 그대로 두고 결과를 한계로 기록했다.

**트레이드오프** — 기본값 유지는 hybrid의 추가 지연(p50 483ms, vector 173ms)을 계속 치른다. ablation에서 `hybrid_plainrrf`는
hit@1 0.600으로 낮지만 hit@10 0.835로 세 기본 방식보다 높아, 현재 가중치 규칙이 1위 정확도와 상위 10위 재현을 맞바꾸고 있다.
`vector_norerank`는 hit@1 0.687로 재정렬이 있는 vector(0.704)보다 낮다. `lexical_nofilter`는 hit@10 0.675로 필터가 있는 lexical보다
높다. `*_nodiv`는 기본과 거의 같다. 세 방식 모두 noise@10은 0.000이다.

**eval 영향** — 결과 파일이 README 붙여넣기용 표, 언어·출처·관점·기대 행동별 부분집합, 청크 단위 표, 방식 정의를 담는다.
`scripts/explain_retrieval.py`로 본 실행 계획은 GIN `idx_paper_chunks_chunk_vector`와 HNSW 인덱스 사용, lexical 약 224ms,
vector 약 3ms, `papers` 순차 스캔(275행)이다.

**알려진 한계** — 질의 형태 관점(query_form 12건)은 세 방식 모두 hit@10 0.167~0.333으로 가장 약하다. 한국어 lexical은 hit@10
0.500이다(`english` FTS). 청크 단위 지표는 15개 질의뿐이다. 275편 규모에서는 HNSW 효과와 운영 규모 지연을 말할 수 없다.
LLM이 만든 질의가 72개로 절반을 차지해 코퍼스 문장과의 어휘 겹침이 실제 사용자 질의보다 클 수 있다.
