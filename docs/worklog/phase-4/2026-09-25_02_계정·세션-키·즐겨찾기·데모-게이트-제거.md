---
title: 계정·세션 키·즐겨찾기·데모 게이트 제거
date: 2026-09-25
area: [backend, frontend]
decision: 로그인·회원가입·세션 API 키·즐겨찾기·데모 모드 제한을 모두 없애고 모든 생성을 서버 OPENAI_API_KEY로 하며, rate limit은 클라이언트 IP만 기준으로 한다
---

**결정과 근거** — 로그인은 사용자별 OpenAI 키를 받기 위한 장치였고, 그 때문에 세션 키 암호화(Fernet), 데모 모드(로그인 전
캐시된 결과만 보기), 계정·관리자 앱, 로그인 화면과 `next` 리다이렉트가 따라왔다. 논문 탐색과 RAG 챗이 목적인 서비스에서 이
표면은 기능보다 보안 경계(리다이렉트 검증, 키 저장)와 코드량을 더 늘렸다. auth·session·admin 앱, 로그인·설정 UI, 즐겨찾기, 암호화된
세션 키를 지우고 모든 생성·챗·질의 임베딩을 서버 `OPENAI_API_KEY`로 한다(e8b57f9). 서버 키가 없으면 생성·챗·에이전트는
503을 돌려준다. 남은 엔드포인트는 13개다. 이 커밋에서 RAGAS 도구 체인을 위해 `pydantic-settings`를 2.8.1에서 2.15.0으로
올렸다.

**트레이드오프** — 사용자별 비용 분리가 사라져 모든 방문자의 호출이 서버 키 비용이 된다. IP당 rate limit 외에 전체 사용량
상한이 없다. 즐겨찾기 같은 개인화 기능도 없다. 대신 커밋 기준 3,208줄이 지워지고 572줄이 더해졌으며, 공격 표면(로그인,
세션, 리다이렉트, 키 저장)이 사라졌다.

**eval 영향** — `tests/unit/test_open_access.py`(18개): 캐시가 있으면 서버 키 없이도 개요를 돌려주고
(`test_cached_overview_is_served_without_server_key`), 캐시가 없고 키도 없으면 503
(`test_missing_cache_without_server_key_returns_503`). `test_security.py`의 `test_account_routes_do_not_exist`가 계정 경로가
없음을 확인한다. 생성 평가는 서버 키 하나로 에이전트와 상세 챗을 같은 조건에서 부른다.

**알려진 한계** — 공개 배포 시 비용 상한은 IP당 한도와 운영자의 키 사용량 알림에 기댄다. AI 결과 캐시를 모든 방문자가
공유하므로 한 방문자가 만든 결과를 모두가 본다.

**트러블슈팅** — 해당 없음
