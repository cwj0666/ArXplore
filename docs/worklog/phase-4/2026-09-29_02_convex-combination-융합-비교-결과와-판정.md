**결정과 근거** — 사전 등록 항목(`2026-09-29_01`, 커밋 7f7063f)의 절차를 그대로 적용했다. convex 모드와 sweep 가족(539f3f5)은 등록
뒤에 구현했고, 그다음에 처음 실행했다. 결과는 `eval/results/fusion_20260929-003515.md`·`.csv`다. 입력 캐시는 09-28 것
(`candidates_20260928-040013.jsonl.gz`, sha256 d7cfdbc24a82)을 그대로 썼고 게이트는 111/111로 통과했다. 설정 1,058개(09-28 전체
958개 + CC 60 + CCK 40)를 한 번에 재생했으므로 fold 배정과 bootstrap 표본이 09-28과 같다. 09-28 설정의 수치도 그대로 재현됐다
(C 0.792, F0 0.785, vector 0.789).

논문 MRR@10(전체 111개, 클러스터 74개):

| 설정 | 상수 수 | MRR@10 | hit@1 | CV MRR@10 (평균 ± SE) |
|---|---|---|---|---|
| 현재 규칙 C | 25 | 0.792 | 0.739 | 0.792 ± 0.037 |
| 표준 RRF k=60 (부분 일치 행 제거 유지) | 1 | 0.785 | 0.730 | 0.785 ± 0.037 |
| vector 단독 | 0 | 0.789 | 0.748 | 0.789 ± 0.038 |
| CC pick `CC_mm_a0.35` (= 전체 데이터 최고 CC) | 1 | 0.805 | 0.766 | CC 가족 0.799 ± 0.037 |
| 보조: 전체 데이터 최고 CCK `CCK_mm_a0.20` (부분 일치 행 유지) | 1 | 0.810 | 0.775 | CCK 가족 0.798 ± 0.035 |

설정 하나의 CV 평균은 전체 데이터 값과 같고 SE만 의미가 있다. CC 전체 데이터 최고값 0.8051에는 다섯 설정이 동률이다(`CC_mm_a0.35`,
`CC_mm_a0.40`, `CC_mm_a0.45`, `CC_tmm_a0.05`, `CC_tmms_a0.05`). 사전 등록대로 이름 순으로 `CC_mm_a0.35`를 골랐다. CC 설정은 모두
상수 1개라 1-SE 규칙은 선택 편향을 줄이지 못한다. 그래서 가족 간 성능은 CV로만 말한다. CC 0.799 ± 0.037은 C 0.792, F1 0.794,
vector 0.789와 SE 안에서 구분되지 않는다.

- **pick은 C와 3개 질의에서 다르고 셋 다 pick이 낫다.** ki-2609.27334-en, lang-abbr-dpo, qf-long-paragraph-en 모두 C 2위 → pick 1위다.
  vector 단독과는 4개가 다르다. 3개는 pick이 낫고(ki-2609.06251-en 6→1위, ki-2609.20804-en 4→1위, lang-en 4→2위),
  mp-first-proposed-en 하나는 vector가 낫다(3위 대 4위, C도 4위). 기준선에서 hybrid와 vector가 갈린 7개 질의로 보면, pick은 6개에서
  두 채널 중 나은 쪽의 순위를 얻고 mp-first-proposed-en만 C와 같이 진다.
- **lang-abbr-dpo 같은 손실을 고친다. 다만 정규화에 달려 있다.** 사후 분석(사전 등록한 판정 항목 밖)으로 C의 세 손실을 보면 원인이
  같다. 두 채널에 모두 나온 다른 논문의 청크가 RRF 항 두 개(+ 교차 보너스)를 받아 1위가 된다. 각 채널의 1위는 정답 논문의 서로 다른
  청크라 한 채널 몫만 받는다. 표준 RRF에서는 두 채널에 다 나온 청크가 순위와 상관없이 한 채널 1위를 이긴다
  (1/61 + 1/(60+r) > 1/61). C도 가중치를 곱할 뿐 같은 구조에 교차 보너스가 더해진다. min-max CC(α 0.35)에서는 vector 1위가 0.65를 받고, 두 채널에 모두 나온 청크는 두 채널에서 다 높아야
  이긴다. lang-abbr-dpo는 `CC_mm`의 20개 α 모두에서 1위다. `CC_tmm`·`CC_tmms`에서는 α ≤ 0.10과 α ≥ 0.60에서만 1위이고, 0.15~0.55에서는
  C처럼 2위다. theoretical 정규화는 lexical strict 점수(≥ 0.85, STRICT_MATCH_BONUS 때문)와 vector 점수를 1 가까이로 압축한다. 그래서
  "두 채널에 다 있음"이 다시 유리해진다.
- **정규화 선택은 CV로는 차이가 작지만 최적 α 위치는 크게 다르다.** 하위 가족 CV는 mm 0.799 ± 0.037, tmm 0.803 ± 0.038, tmms
  0.803 ± 0.038이다. 최고 α는 mm 0.35~0.45, tmm·tmms 0.05다. fold 선택은 안정적이다(`CC_mm_a0.35` 40/50, `CC_tmm_a0.05` 49/50).
  논문 TM2C2의 기본값 α_sem 0.8(여기 표기 lexical 0.2, `CC_tmm_a0.20`)은 MRR@10 0.792, hit@1 0.739로 C와 같다.
- **α = 0.00 점검값은 vector 단독과 같다**(0.7894). 사전 등록 때 적은 대로 lexical 채널은 78개 질의에서 비고(퇴화 없음), mm
  lexical 정규화는 7개 질의에서 퇴화했다(후보 1개, 모두 1.0). tmm·tmms와 vector 쪽의 퇴화는 0이다.
- **보조(CCK, 부분 일치 행 유지)**: mm은 α 0.20에서 0.810으로 가장 높았지만 가족 CV는 0.798 ± 0.035로 CC와 같다. tmm은 α가
  0.10을 넘으면 0.62~0.72로 떨어진다. RRF에서처럼(REF 0.709) 부분 일치 행은 점수 융합에서도 α가 커지면 해롭다. 선택·판정에는 쓰지
  않았다.

사전 등록 규칙을 기계적으로 적용한 판정은 다음과 같다.
- 규칙 (1): pick − C ΔMRR@10 +0.0135, 95% CI [+0.000, +0.031]로 0을 포함한다 → 더 단순한 `CC_mm_a0.35`(상수 1개 대 25개)로
  교체한다. 하한이 정확히 0인 것은 pick이 C에게 지는 질의가 없어서다. 세 질의의 클러스터를 하나도 뽑지 않은 표본이 0을 만든다.
  Δhit@1은 +0.027 [+0.000, +0.061]이다.
- manual 비회귀 조건: pick − C [+0.000, +0.060], 상한 ≥ 0으로 충족한다.
- 규칙 (3): pick − vector 단독 +0.0158 [−0.001, +0.038]로 유의하지 않다 → vector 단독 근거로 보고하고 기본 검색 방식은 사용자에게
  넘긴다. manual에서는 +0.004 [−0.006, +0.017]이고 hit@1은 같다.
- 규칙 (4)(논문 주장 점검, 제품 판정에는 쓰지 않음): pick − 표준 RRF(k=60) +0.0200 [+0.005, +0.040] → 이 설정에서 "CC > RRF"를
  구간상 재현했다. pick은 같은 질의로 60개 중에서 고른 설정이라 이 구간은 선택 편향만큼 낙관적이다. CV로는 CC 0.799 대 F0 0.785로
  SE(0.037) 안의 차이다.

인용(Bruch, Gai, Ingber, ACM TOIS 42(1), 2023, doi:10.1145/3596512, arXiv:2210.11934)은 Crossref 서지와 arXiv 본문으로 확인했다.
논문 주장 네 개에 이번 결과를 대 보면 다음과 같다. (a) CC > RRF: 위와 같이 전체 데이터 구간으로는 재현, CV로는 구분되지 않는다.
(b) RRF가 매개변수에 민감하다: 재현하지 못했다. 표준 RRF는 k 10~100에서 순위가 같다(09-28). 채널이 30개로 얕고 두 채널이 겹치는
청크가 질의당 평균 0.3개라 k가 순서를 바꿀 여지가 거의 없다. 논문은 채널당 1,000개 후보를 썼다. (c) 정규화 선택에 대체로 무관하다:
α를 맞춘 뒤의 CV는 비슷하다. 그러나 최적 α가 정규화마다 다르고 DPO 유형 손실의 수정 여부도 정규화에 달려 있어, 고정 α에서는
무관하지 않다. (d) 표본 효율: fold마다 같은 α를 고르는 것(40/50, 49/50)과 맞지만 학습 크기를 바꿔 본 직접 검증은 아니다.

제품 융합 설정(`DEFAULT_HYBRID_FUSION`)과 기본 검색 방식은 바꾸지 않았다. 규칙 (1)은 C를 `CC_mm_a0.35`로 바꾸라고 가리킨다. 09-28
규칙 (1)은 표준 RRF를 가리켰는데, 이번에는 규칙 (4)에서 CC pick이 그 표준 RRF보다 구간상 낫게 나왔다. 규칙 (3)은 어느 hybrid 설정도
vector 단독보다 유의하게 낫지 않다고 본다. 교체 여부와 기본 검색 방식은 사용자가 정한다.

**트레이드오프** — 사전 등록한 설계를 그대로 따랐고 벗어난 점은 없다. 등록한 격자 밖의 설정은 재지 않았다. 동률 5개 중 pick은 등록한
이름 순 규칙으로 정했다. C의 손실 원인 분석과 CC 설정별 점수 확인(질의 4개)은 결과를 본 뒤 한 사후 분석이다. 설명에만 쓰고 판정에는
쓰지 않았다. 규칙 (1)의 "0을 포함"은 pick이 C에게 한 번도 지지 않은 경계 상황이다. 문구대로 적용했지만 "구간이 0을 포함하니 차이가
없다"로 읽으면 안 된다. 순위가 바뀐 3개 질의에서는 모두 pick이 이긴다. 거꾸로, 개선의 근거가 3개 질의(1.35%p)뿐이라는 점도 같은 무게로
적는다.
