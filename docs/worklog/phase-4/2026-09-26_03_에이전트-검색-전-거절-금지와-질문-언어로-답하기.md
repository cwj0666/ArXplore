title: 에이전트 검색 전 거절 금지와 질문 언어로 답하기
date: 2026-09-26
area: [agent, eval]
decision: 에이전트 프롬프트에 "논문 관련 질문은 낯선 이름·수치여도 검색을 먼저 하고 결과를 보고 판단한다, 검색 없이 거절하지 않는다"와 "사용자의 마지막 메시지와 같은 언어로 답한다"를 더하고, 존댓말 규칙은 한국어 답변에만 적용한다
---

**결정과 근거** — run2(`generation_20260925-233840.md`) 에이전트 llm_synth 부분집합의 faithfulness 0.688(14건)을 레코드
단위로 나눠 보면 15건 중 4건이 거절이고, 거절문에 대한 faithfulness(0.71, 0.33, 0.20)가 평균을 끌어내렸다. 거절 4건의
원인은 셋이다. (1) `cs-12667`("TAPe+ML v3의 GTX 1070 Ti 프레임당 추론 시간")은 `hit_arxiv_ids`가 비어 있어 검색 도구를
한 번도 부르지 않고 "수집되어 있지 않을 수 있습니다"라고 답했다. 규칙 4(범위 밖이면 짧게 거절)가 낯선 모델명에 먼저 반응한
것이다. (2) `cs-2121`·`cs-472`는 정답 논문은 hit에 있었지만 정답 청크(편집 물체 비교, Free Flow-S 메모리)가 5개 결과에
없었다. (3) `cs-11328`은 "Pro-618"이 5개 발췌문 중 2개에 있었는데도 없다고 답했다. 같은 검색 평가에서는 이 질의의
chunk hit@5가 1.0이라, 에이전트가 도구에 넘긴 질의가 원문과 달랐을 가능성이 크다.

프롬프트로 고칠 수 있는 것은 (1)이다. 규칙 4에 "논문에 관한 질문은 모델명·수치·용어가 낯설어도 범위 밖이라고 짐작하지 말고
반드시 검색 도구를 먼저 호출한 뒤 판단한다. 검색하지 않고 거절하지 않는다"를 붙였다. (2)·(3)은 검색 깊이와 질의 재작성
문제라 이 항목에서 다루지 않는다.

같은 답변 파일에서 언어 불일치도 확인했다. 영어 질의 62건 중 22건(한글 비율 30% 초과)을 한국어로 답했다. 프롬프트 마지막
줄 "반드시 뉴스 브리핑 전문가처럼 존댓말(~합니다)로 출력하세요"가 언어와 무관하게 한국어 종결어미를 요구한 것이 원인이다.
형식 규칙 4로 "사용자의 마지막 메시지와 같은 언어로 답한다(제목·링크는 원문)"를 더하고, 존댓말 규칙을 "한국어로 답할 때는"으로
한정했다(`src/core/prompts/agent.py`).

**트레이드오프** — 검색 전 거절 금지는 명백히 무관한 질문(요리 등)에도 도구 호출 1회를 강제해 지연과 비용이 든다. 규칙 4의
"논문과 무관한 질문은 짧게 거절"은 그대로 두었으므로 모델이 논문 관련 여부를 먼저 판단하는 구조는 같고, 낯선 이름을 "무관"으로
오판하는 것만 막는다. 답변 언어 규칙은 한·영 혼용 질의에서 어느 쪽을 고를지 모델에 맡긴다. 거절문에 faithfulness를 매기는
채점 규칙은 바꾸지 않았다. 거절이 맞는지는 행동 지표(answer 케이스의 refused 건수)로 따로 읽는다.

**eval 영향** — `test_agent_guardrails.py::test_system_prompt_contains_guardrail_rules`가 규칙 4~6과 새 두 규칙 문구,
존댓말 규칙이 한국어 한정으로 한 번만 나오는지 고정한다. 재측정 지점: 에이전트 answer 케이스의 refused 건수(run2 7건),
llm_synth faithfulness(0.688), 영어 질의의 한국어 답변 비율(22/62). 언어 일치는 아직 행동 지표가 아니라 답변 파일에서 한글
비율로 셌다. 재측정은 DB와 API 키가 있어야 하며 이 항목 시점에는 하지 않았다.

**알려진 한계** — 프롬프트 규칙이라 모델이 어기면 막을 장치가 없다. 답변 언어 지표가 없어 재발을 자동으로 잡지 못한다.
청크 단위 질문에서 정답 청크가 5개 결과에 안 들어오는 문제(2)와 도구 질의 재작성 문제(3)는 남아 있다.

**트러블슈팅** — 영어 질문에 한국어로 답함

- 증상: run2 에이전트 답변 중 영어 질의 62건의 22건이 한국어였다(`ki-*-en` 11건, `lang-abbr-*` 3건, 거절문 5건 등).
- 원인: 시스템 프롬프트 마지막 줄이 언어와 무관하게 존댓말 종결어미를 요구했다.
- 확인 방법: `answers_run2.jsonl`에서 `lang=en`·`mode=agent` 답변의 한글 글자 비율을 세어 30% 넘는 레코드를 나열했다.
- 해결: 질문 언어로 답하는 규칙을 더하고 존댓말 규칙을 한국어 답변에 한정했다. 단위 테스트로 문구를 고정했다. 비율의 전후
  비교는 재측정 뒤에 덧붙인다. (2026-09-26 재측정 추가) `answers_20260926-103836.jsonl`(layout_pdf 코퍼스, 커밋 72051ff)에서
  `lang=en`·`mode=agent`·오류 없는 답변 61건 중 한글 비율 30% 초과는 4건(`lang-abbr-rlhf`, `oc-personal-opinion-en`,
  `sf-inject-en`, `sf-system-prompt-en`)이다. 같은 기준으로 `answers_run2.jsonl`을 다시 세면 22/63이다.
- 재발 방지: 프롬프트 문구 테스트. 답변 언어 행동 지표는 아직 없다.

사례 2 — 검색 없이 거절

- 증상: `cs-12667`의 `hit_arxiv_ids`가 비어 있고 `retrieval_mode`가 None인데 답변은 "수집되어 있지 않을 수 있습니다"였다.
- 원인: 범위 규칙(규칙 4)이 낯선 모델명·하드웨어 이름을 범위 밖으로 오판하게 했고, 프롬프트 첫 줄의 "도구를 최소 1번 이상
  호출"만으로는 막지 못했다.
- 확인 방법: 답변 파일의 `hit_arxiv_ids`·`citations`·`retrieval_mode`를 확인했다. 같은 질의의 검색 평가는 paper hit@5 1.0이다.
- 해결: 규칙 4에 검색 전 거절 금지를 명시했다. 효과는 재측정에서 answer 케이스의 refused 건수로 확인한다. (2026-09-26 재측정
  추가) `generation_20260926-103836.md`에서 에이전트 answer 케이스 거절은 7건 그대로다(`cs-12637`, `cs-12189`, `cs-1892`,
  `ev-results-table`, `ev-appendix`, `ev-figure-caption`, `sf-inject-embedded`). 청크 합성 질의를 다시 만들어 `cs-12667`은
  질의셋에 없으므로 이 사례를 직접 확인하지는 못했다. 에이전트 llm_synth faithfulness는 0.657(10건)이다.
- 재발 방지: 프롬프트 문구 테스트와 llm_synth 케이스가 생성 평가에 상주한다.
