---
title: hybrid 융합 상수 재검증 사전 등록
date: 2026-09-28
area: [retrieval, eval]
decision: 근거 기록이 없는 hybrid 융합 상수(9880127)를 캐시한 채널 후보의 융합 재생, ko/en 쌍을 묶은 클러스터 단위 반복 층화 CV, 1-SE 규칙, 클러스터 paired bootstrap으로 다시 고르기로 하고, 측정 전에 설정 가족·주 지표·비교 쌍·판정 규칙을 이 항목에 고정한다
---

**결정과 근거** — hybrid 융합(`_merge_hybrid_candidates`)에는 손으로 고른 상수가 약 20개 있다. RRF k=60, 교차 보너스 0.015,
질의 토큰 5개 이상이면 lexical×0.85·vector×1.05, lexical 1위 confidence < 0.3이면 ×0.45·×1.1, < 0.5이면 ×0.7·×1.05, 상위 5개가
겹치지 않고 confidence < 0.4이면 ×0.75·×1.08, 가중치 하한 0.2·0.5, lexical 품질 가중 구간(0.2/0.3/0.5/0.8 미만 → 0.2/0.4/0.65/0.85,
그 이상 1.0)이다. 모두 9880127(2026-04-06, "refine retrieval ranking and noise filtering")에서 들어왔고 근거가 남아 있지 않다.
지금까지의 증거는 `hybrid_plainrrf` ablation뿐이다. 첫 실측(`20260925-225658.md`)에서 hit@1 0.600 / hit@10 0.835, layout_pdf
재측정(`20260926-103105.md`)에서 논문 hit@1 0.577, 청크 hit@5 0.727이었다. 그런데 이번 리팩터링에서 이 ablation이 가중치를 끄는
것 말고도 lexical 부분 일치 행(`strict_match=False`)을 다시 받아들이고 있었다는 것을 확인했다. 따라서 이 수치는 두 변경이 섞인 값이다.
layout_pdf 재측정에서 hybrid MRR@10은 0.787, vector는 0.785로 거의 같았다.

측정 설계는 세 단계다.

(1) 제품 코드 리팩터링. 융합 상수를 `HybridFusionConfig`(`src/integrations/hybrid_fusion.py`)로 모았다. 융합은 순수 함수
`fuse_hybrid_candidates`, 다양성은 `apply_paper_diversity`로 분리했다. `PaperRetriever`는 기본 설정으로 이 두 함수를 부른다. 기본
설정이 리팩터링 전(89b100f) 출력과 같다는 것은 합성 입력 60개의 전체 필드 지문으로 고정했다
(`tests/unit/fixtures/hybrid_fusion_golden.json`). 표준 RRF 프리셋 `STANDARD_RRF_FUSION`은 삭제한 `eval.runner.plain_rrf`와 순서·점수가
같다(동점 규칙, 부분 일치 행 유지까지). 제품 hybrid 경로가 융합에 넘기는 입력은 `hybrid_fusion_inputs`가 만든다.

(2) 캐시와 재생. `scripts/eval_dump_candidates.py`가 질의마다 `hybrid_fusion_inputs(k=10)`(채널당 30개, 저장소 요청 150개)와
제품 `search_paper_chunks_by_hybrid`, vector·lexical 단독 결과를 기록한다. 임베딩은 질의당 한 번만 요청한다. 재생은
`fuse_hybrid_candidates` → `apply_paper_diversity`다. 게이트 조건: 현재 기본 설정으로 재생한 순위(chunk_id, arxiv_id)가 기록한
제품 순위와 111개 질의 모두에서 같아야 한다. 하나라도 다르면 sweep은 결과를 쓰지 않는다.

(3) 비교. 질의셋은 `eval/queries.jsonl`(sha256 82e4a51cce90)의 검색 평가 대상 111개(ko 58 / en 53; known_item 57, manual 43,
llm_synth 11)다. 설정 가족과 격자는 다음과 같다(모두 제품과 같이 부분 일치 행 제거를 켠다).

| 가족 | 내용 | 설정 수 |
|---|---|---|
| R0 | vector 단독, lexical 단독 (캐시 후보에 다양성만) | 1 + 1 |
| F0 | 표준 RRF, k ∈ {10, 20, 40, 60, 100} | 5 |
| F1 | 고정 가중치 w_lex ∈ {0, 0.1, …, 1.0}, w_vec = 1, × k × 품질 가중 on/off × 교차 보너스 {0, 0.015} | 220 |
| F2 | confidence 선형 w_lex = w_min + (1 − w_min)·clip(conf/tau, 0, 1), w_min ∈ {0.1, …, 0.9} × tau ∈ {0.2, 0.3, 0.5, 0.8} × k × 품질 × 보너스 | 720 |
| C | 현재 규칙 그대로 | 1 |
| CF | 현재 규칙의 방법 가중 × 품질 가중 × 교차 보너스 켬/끔 2^3 요인 배치 | 8 |

비교용 REF 2개(부분 일치 행을 버리지 않는 C, 예전 `hybrid_plainrrf`)는 선택 대상이 아니다. 주 지표는 전체 111개 질의의 논문
MRR@10이다. hit@1/5/10, recall@10, 청크 hit@5(청크 정답 11개)와 source·lang 부분집합은 함께 보고한다.

같은 논문을 ko/en으로 물은 쌍은 독립 표본이 아니므로 CV와 bootstrap 모두 클러스터 단위로 다룬다. 클러스터 키는 id 끝의
`-ko`/`-en`을 뗀 값이고(`cluster_key`), 짝이 없는 질의는 혼자 한 클러스터다. 검색 평가 대상 111개는 74개 클러스터다(쌍 37 =
known_item 27 + manual 10, 혼자 37). 키 규칙을 그대로 적용하므로 두 언어가 서로 다른 논문을 정답으로 갖는 케이스 쌍 8개(multi_paper
3, query_form 5)도 한 클러스터로 묶인다. 묶으면 구간이 넓어지는 쪽이라 보수적이다.

가족별 성능은 클러스터 층화 5-fold를 10번 반복한 CV(seed 20260928)로 낸다. 쌍의 두 질의는 늘 같은 fold에 들어간다. 층은 클러스터
단위로 source × (쌍이면 `pair`, 혼자면 lang)이다. 쌍은 ko/en을 하나씩 담으므로 lang을 따로 층에 넣지 않아도 fold마다 언어가 섞인다.
층마다 클러스터를 섞은 뒤 그 층의 질의가 가장 적은 fold에 넣고, 동률이면 전체 질의가 가장 적은 fold에 넣는다. 현재 질의셋에서
fold 크기는 22/22/22/22/23이다. 학습 fold에서 MRR이 가장 높은 설정을 고르고(동률이면 상수가 적은 쪽) 남긴
fold에서 잰다. 결과는 평균 ± SE(반복마다 fold 점수 표준편차/√5의 평균)다. 최종 선택(pick)은 선택 가능한 가족(F0·F1·F2·C·CF)
전체에서 고른다. 전체 데이터 MRR 최고 설정에서 그 설정의 CV SE를 뺀 값이 기준이고, 기준 이상인 설정 중 상수가 가장 적은 설정이
pick이다(1-SE 규칙). 상수 수는 `count_parameters`로 센다: rank constant 1, 교차 보너스 1, 품질 가중 8, 고정 가중치 1, confidence
선형 2, 현재 규칙 15이고, C는 25개다. paired bootstrap은 클러스터를 복원 추출하는 10,000회(seed 20260928, manual은 20260929)다.
표본마다 통계량은 질의 평균(뽑힌 클러스터들의 질의 차이 합 / 뽑힌 질의 수)이다. ΔMRR@10과 Δhit@1의 95% 백분위 구간을 내고,
표에 질의 수와 클러스터 수를 함께 적는다. 비교 쌍은 pick − C, pick − F0(k=60), pick − vector 단독, C − F0(k=60)이고, 참고로 C − vector 단독도 낸다.
각 쌍을 전체와 manual 부분집합(43개, 클러스터 33개)에서 따로 낸다.

판정 규칙은 다음과 같다(sweep 리포트의 "사전 등록 규칙 판정" 절이 기계적으로 적용한다).

- 비회귀 조건: manual 부분집합에서 pick − C ΔMRR@10 구간의 상한이 0보다 작으면 교체하지 않는다.
- (1) pick − C 구간이 0을 포함하면 더 단순한 pick으로 교체한다. 구간 전체가 0보다 크면 역시 교체한다.
- (2) C가 유의하게 나으면(구간 상한 < 0) 현재 규칙을 유지한다. 이때 CF 요인 배치의 주효과로 어느 요인이 기여하는지 기록한다.
- (3) 최종 설정(pick 또는 C)이 vector 단독보다 유의하게 낫지 않으면(구간 하한 ≤ 0) vector 단독 근거로 보고하고, 기본 검색
  방식의 결정은 사용자에게 넘긴다.

현재 규칙은 질의셋보다 먼저 정해졌다(9880127은 2026-04-06, 질의셋은 2026-09-25 이후 생성). 따라서 C, F0(k=60), vector 단독의
전체 데이터 수치에는 이 질의셋에 맞춘 조정이 없다. 반면 k 격자, F1, F2, CF 선택은 같은 질의로 고르므로 CV 값으로만 가족 간
성능을 말한다. pick − X 구간은 선택 편향만큼 낙관적이라는 점도 리포트에 적는다.

**트레이드오프** — 재생 방식에는 두 가지 이점이 있다. 설정 약 960개를 DB·임베딩 호출 없이 한 번에 비교할 수 있고(합성 111개
질의로 약 11초), 임베딩 API의 비결정성이 설정 간 차이에 섞이지 않는다. 대신 캐시에 고정된 것은 바꿔 볼 수 없다. 채널 후보 수
(`hybrid_branch_limit`), SQL 안의 content_role·섹션 가중, lexical·vector 재정렬, 부분 일치 행 제거가 그렇다. 부분 일치 행 제거는
REF 두 줄로만 본다. R0는 hybrid 입력 30개에 다양성만 적용한 순위라 제품 vector 단독 검색과 다를 수 있다. 제품 vector 단독은
저장소 요청이 50개이고 HNSW 후보 수도 다르다. 기록 스크립트가 다른 질의 수를 출력한다. 1-SE 규칙의 "단순함"은 상수 개수로 정의했다.
품질 가중 구간을 8개로 세는 것은 한 가지 선택이다. 동률인 설정 사이에서는 이름 순으로 정해져 k 값 선택이 임의적일 수 있다.
그래서 기준 이상 설정 목록을 리포트에 함께 남긴다. 신뢰구간은 BCa가 아닌 백분위 방식을 썼다.

**eval 영향** — 새 측정 지점은 `eval/results/fusion_<timestamp>.{md,csv}`(가족별 CV, 1-SE 선택, 주요 설정·부분집합 표, CF 요인
배치와 주효과, bootstrap 표, 전체 설정 CSV)와 `eval/cache/candidates_<timestamp>.jsonl.gz`다. 캐시는 결과와 함께 커밋한다. chunk_id가
코퍼스에 묶여 있어 캐시 없이는 같은 비교를 재현할 수 없기 때문이다. `hybrid_plainrrf`는 이제 `STANDARD_RRF_FUSION`으로 돌고, 예전
구현과 같은 순위라는 것을 테스트가 확인한다. 테스트: `test_retrieval_fusion.py`의 `TestFusionRefactorGolden`, `TestFusionConfig`,
`TestStandardRrfPreset`, `test_fusion_sweep.py`(캐시 왕복·게이트·클러스터 키·쌍이 fold를 넘지 않음·CV·클러스터 bootstrap·1-SE·판정
규칙·스크립트).

**알려진 한계** — 질의 111개의 단일 질의셋이다. manual은 43개, 청크 정답은 11개라 부분집합 구간이 넓다. 클러스터는 id의
ko/en 짝만 본다. 서로 다른 id가 같은 논문을 정답으로 갖는 경우(카탈로그 케이스와 known_item이 같은 논문을 겨누는 경우 등)의
상관은 모형에 없어, 그만큼 구간이 여전히 좁을 수 있다. pick − X 구간은 같은 질의로 pick을 고른 선택 편향만큼 낙관적이다. 판정은 MRR@10만 보고 hit@10은
보조로만 쓴다. 코퍼스를 다시 만들면 chunk_id가 바뀌므로 캐시를 다시 기록해야 한다. 이 항목은 측정 전에 쓴 것이고, 결과와 채택
여부는 별도 항목에 기록한다.

**트러블슈팅** — 해당 없음
