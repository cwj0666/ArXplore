**결정과 근거** — phase-0에서 추가한 130개에 이어 151개의 단위 테스트를 더했다(8d20944). 대상은 검색 결과를 바꾸는 계산이다.
hybrid의 RRF(k=60) 점수와 두 채널 동시 hit 보너스, lexical 신뢰도에 따른 가중치 이동, references·목차 필터, 논문당 2청크
다양성, 상세 요약 그래프의 LLM 호출 예산(4개 버킷 입력에서 섹션 요약 11 + 버킷 병합 4 + 최종 1 = 16회), 설정 파싱이다.
CI는 5잡으로 나눴다. python(ruff, `pytest tests/unit`, `manage.py check`, `makemigrations --check`), integration(pgvector
서비스 컨테이너 위의 `pytest tests/integration -m integration`), frontend(typecheck, build), infra(더미 `.env`로
`docker compose config`, hadolint), security(gitleaks 전체 히스토리). gitleaks 기본 규칙에 Tailscale 키가 없어
`tailscale-auth-key` 규칙을 더했다.

**트레이드오프** — 단위 테스트는 가짜 커서로 SQL 문자열과 파라미터를 검사하는 것이 많아, SQL이 실제로 맞는지는 integration
잡만 확인한다. integration 잡은 수집된 테스트가 0개면 실패하게 했다(f229c59). 마커 실수로 통합 테스트가 조용히 빠지는 것을
막기 위해서다. gitleaks 액션은 조직 저장소에서 유료 라이선스가 필요해 CLI를 체크섬 검증 후 직접 설치한다.

**eval 영향** — `tests/unit/test_retrieval_fusion.py`의 `test_rrf_scores_and_both_channel_bonus`,
`test_low_lexical_confidence_shifts_weight_to_vector`, `test_retrieval_filters.py`, `test_summary_graph.py`의
`test_full_four_bucket_input_makes_sixteen_llm_calls`, `test_settings.py`. 현재 단위 테스트는 847개, 통합 테스트는 37개이고
fork(cwj0666/ArXplore)에서 5잡이 모두 통과한다. 검색 평가의 `hybrid_plainrrf` ablation(가중치·보정 없는 표준 RRF)이 이
가중치 규칙의 효과를 따로 잰다.

**알려진 한계** — 프론트엔드는 타입 검사와 빌드만 하고 동작 테스트가 없다. 단위 테스트가 고정하는 것은 현재 상수와 공식이지
그 값이 좋은지가 아니다. 좋은지는 검색 평가가 판단한다.

**트러블슈팅** — 해당 없음
