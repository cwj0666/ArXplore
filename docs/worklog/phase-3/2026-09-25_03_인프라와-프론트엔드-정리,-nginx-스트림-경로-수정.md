title: 인프라와 프론트엔드 정리, nginx 스트림 경로 수정
date: 2026-09-25
area: [infra, frontend]
decision: vite를 dev 프로필 뒤로 옮기고 healthcheck·비root 이미지·requirements 3분할·nginx 보안 헤더를 두며, 상세 챗 스트림 경로를 nginx가 Django로 보내게 고치고, 프론트엔드를 SPA 내비게이션·404·ErrorBoundary·URL 동기화 목록 상태로 바꾼다
---

**결정과 근거** — 인프라(dd3b013): vite 개발 서버를 `dev` 프로필로 옮겨 기본 실행에서 빼고 loopback에만 바인딩한다(f229c59).
django·nginx·postgres-local에 healthcheck를 두고 nginx는 django가 healthy일 때 시작한다. Django 이미지는 비root 사용자
(`app`, UID 1000)로 돈다. 의존성은 `requirements.txt`(런타임), `requirements-dev.txt`(테스트·린트), `requirements-airflow.txt`
(Airflow 공식 constraints와 함께 설치)로 나눴다. nginx가 `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`와
gzip을 맡는다(515e211). 개발 프록시는 클라이언트가 보낸 `X-Real-IP`·`X-Forwarded-For`를 소켓 주소로 덮어쓰고, CSRF 신뢰
출처에 개발 서버 출처(:5173)를 넣었다(f229c59). 프론트엔드: 화면 이동을 react-router `Link`/`navigate`로 바꾸고 404 화면과
ErrorBoundary를 두었으며, 목록 상태(검색어·페이지)는 URL 쿼리가 원본이다. 모달은 Esc·포커스 복귀를 지원하고 색상은
`:root` CSS 토큰을 쓴다.

**트레이드오프** — 프로필을 나누면 실행 명령이 길어져 CLAUDE.md와 README에 프로필별 명령을 적어야 했다. 보안 헤더를 nginx에만
두어 Django를 직접 띄우는 개발 경로에는 헤더가 없다. requirements 분할은 세 파일의 버전 정합성을 사람이 맞춰야 한다.

**eval 영향** — CI infra 잡이 더미 `.env`로 `docker compose config`를 두 compose 파일에 돌리고 Dockerfile에 hadolint를 건다.
frontend 잡이 타입 검사와 빌드를 한다. dev 프록시의 IP 덮어쓰기는 rate limit 테스트(`test_security.py`의
`test_uses_configured_proxy_header`)가 전제하는 "앞단이 헤더를 덮어쓴다"를 개발 환경에서도 성립시킨다.

**알려진 한계** — nginx 라우팅과 헤더를 확인하는 자동 테스트가 없다. gunicorn gthread(워커 4 × 스레드 8)라 SSE 스트림 하나가
스레드 하나를 오래 점유한다.

**트러블슈팅** — 상세 챗 스트림 요청이 index.html을 받음

- 증상: nginx를 거치면 상세 챗 스트림 요청 `/papers/<id>/chat/stream/`이 Django 응답 대신 React `index.html`을 받았다.
- 원인: nginx에 이 경로를 프록시하는 location이 없어 마지막 SPA 폴백(`try_files $uri $uri/ /index.html`)에 걸렸다. phase-2에서
  상세 챗 스트림 경로를 더할 때 nginx 설정을 같이 고치지 않았다.
- 확인 방법: `docker/nginx/nginx.conf`의 location 목록과 Django URL 목록을 대조해 스트림 경로가 빠진 것을 확인했다.
- 해결: 두 SSE 경로를 정규식 location `^/papers/(assistant|[^/]+/chat)/stream/$` 하나로 묶고 `proxy_buffering off`,
  `gzip off`, `proxy_read_timeout 300s`로 프록시했다(dd3b013).
- 재발 방지: CLAUDE.md에 "새 API 경로는 nginx location과 `frontend/vite.config.ts` 프록시에 같이 넣는다"를 적었다. 이 규칙을
  검사하는 자동 테스트는 없다.
