---
title: 독립 리뷰어 두 명의 3회 리뷰와 코드 위생
date: 2026-09-25
area: [tooling, docs]
decision: 계획과 코드 diff를 서로 독립된 리뷰어 두 명(Opus 서브에이전트, Codex CLI gpt-6-astra)에게 각각 3회씩 리뷰받아 매 회차 지적을 고치고, AI가 더한 코드 주석을 지우며 ruff format을 CI에서 강제한다
---

**결정과 근거** — 작성자와 같은 맥락을 가진 리뷰어는 같은 가정을 공유하므로, 서로의 결과를 보지 않는 리뷰어 둘에게 같은
대상을 맡기는 방식(산타 방식)을 썼다. 리뷰어는 Opus 서브에이전트와 Codex CLI(gpt-6-astra)다. 계획을 3회, 코드 diff를 3회
리뷰받았고 모든 회차에서 지적이 나왔다. 각 회차의 지적은 커밋으로 고쳤다(f229c59, 515e211, 4c358d5). 이어서 기준선 이후
추가된 코드 주석을 Python·TypeScript·Dockerfile·nginx 소스에서 지우고(지시문과 docstring은 유지), Python 전체에 ruff format을
적용해 CI python 잡에서 `ruff format --check`로 강제했다(46c95e5). 시크릿 스캔은 단위 테스트의 키 모양 더미 문자열 때문에
실패해 더미 값을 키처럼 보이지 않는 값으로 바꾸고 과거 커밋의 fingerprint를 허용 목록에 넣었다(af5abfc).

**트레이드오프** — 회차마다 두 리뷰어의 지적을 대조·중복 제거하고 고치는 시간이 들었다. 3회에서 멈춘 것은 비용 기준이고,
3회차에도 지적이 나왔으므로 "지적이 없어질 때까지"를 보장하지 않는다. 주석을 지우면 근거는 docstring, 문서, 테스트 이름,
worklog로 옮겨야 한다.

**eval 영향** — 리뷰 지적으로 더해진 회귀 테스트가 각 영역 테스트 파일에 있다. 예:
`test_prepare_pipeline.py`의 `test_chunk_write_failure_does_not_mark_content_unchanged_on_retry`,
`test_agent_guardrails.py`의 `test_lookalike_domain_is_not_attributed_to_an_arxiv_hit`, `test_prepare_jobs.py`의
`test_enqueue_merges_payload_so_requeued_force_survives`.

**알려진 한계** — 리뷰 지적 목록은 커밋 메시지에만 남고 별도 기록이 없다. 리뷰어가 둘 다 놓친 결함은 이 방식으로 잡히지
않으며, 실제로 phase-4 로컬 코퍼스 실측에서 서로게이트 문자·NUL 문자·긴 질의 결함이 새로 나왔다.

**트러블슈팅** — 해당 없음
