# 작업 로그(worklog) 규약

페이즈별 작업 로그는 "무엇을 만들었나"가 아니라 **"왜 그렇게 결정했고, 무엇을 포기했고, 그래서 무엇을 측정할 수 있게
됐나"**를 남긴다. 코드와 커밋 메시지는 무엇이 바뀌었는지를 보여 주고, 결정의 이유와 대안, 측정 지점, 겪은 문제는 이
디렉터리에 둔다.

## 구조

```
docs/worklog/
  README.md                         이 규약
  TROUBLESHOOTING.md                자동 생성. 모든 항목의 트러블슈팅 절 모음. 손으로 고치지 않는다
  phase-<n>/
    INDEX.md                        자동 생성 색인. 손으로 고치지 않는다
    YYYY-MM-DD_NN_<제목>.md           항목 하나 = 파일 하나. NN은 같은 날 순번(01부터)
```

- 찾을 때는 `phase-<n>/INDEX.md`만 읽고 필요한 파일만 연다. 색인 한 줄에 날짜·제목·영역·결정 한 줄이 있다.
- 겪은 문제를 찾을 때는 `TROUBLESHOOTING.md`를 연다. 사례가 있는 항목의 트러블슈팅 절이 페이즈별로 모여 있다.
- 파일 단위라 같은 파일에 append하지 않으며 충돌이 없다.

## 항목 만들기

```bash
.venv/bin/python scripts/worklog.py new "제목" --phase 4 --area retrieval,eval
.venv/bin/python scripts/worklog.py index      # INDEX.md와 TROUBLESHOOTING.md 재생성 (커밋 전에)
.venv/bin/python scripts/worklog.py check      # 형식·생성 파일 검사. pre-commit 훅과 CI가 같은 명령을 돈다
```

`new`는 오늘 날짜와 다음 순번으로 템플릿 파일을 만든다. 파일을 채운 뒤 `index`를 돌리고 항목 파일과 생성 파일을 함께
커밋한다. `check`는 항목 형식이 어긋나거나 생성 파일이 항목과 다르면 실패한다.

## 항목 형식

```markdown
---
title: <제목>
date: YYYY-MM-DD
area: [retrieval, eval]
decision: <한 줄. 색인에 그대로 실린다>
---

**결정과 근거** — 무엇을 어떻게 하기로 했고, 왜 그런가. 근거가 실측이면 방법·결과를 포함한다.

**트레이드오프** — 고려한 대안 / 채택 이유 / 지불한 비용. 미룬 것·좁힌 것·복잡해진 것을 적는다.

**eval 영향** — 이 결정이 만드는(또는 없애는) 측정 지점. 테스트 파일, 평가 지표 이름을 적는다.

**알려진 한계** — 이 결정으로 못 잡게 된 것. 테스트로 등재한 것은 테스트 파일·이름을 명시한다.

**트러블슈팅** — <사례 제목>

- 증상: 관찰된 현상
- 원인: 코드·데이터 수준의 원인
- 확인 방법: 재현하거나 원인을 확정한 방법
- 해결: 바꾼 것과 검증(테스트 파일, 지표 전후 수치, 커밋 해시)
- 재발 방지: 같은 문제를 다시 잡는 장치(테스트, CI, 설정, 문서)
```

- `area` 어휘: `pipeline` `retrieval` `agent` `backend` `frontend` `eval` `infra` `docs` `tooling`. 여러 개 가능. 어휘를
  늘리려면 `scripts/worklog.py`의 `AREAS`와 이 목록을 함께 고친다.
- 다섯 섹션은 생략하지 않고 위 순서를 지키며, 섹션 제목은 줄 머리에 둔다. 해당 없으면 "해당 없음"이라고 쓴다. 생략은
  "안 적은 것"과 "없는 것"을 구분하지 못하게 한다.
- 트러블슈팅 절은 "해당 없음"으로 시작하거나, `- 증상:` `- 원인:` `- 확인 방법:` `- 해결:` `- 재발 방지:` 다섯 줄을 이
  순서로 가진 사례를 하나 이상 담는다. 사례가 둘 이상이면 두 번째 사례 앞에 `사례 2 — <제목>` 줄을 둔다. `check`가 라벨
  순서를 검사하고, `index`가 사례가 있는 절을 `TROUBLESHOOTING.md`로 모은다.
- 수치는 결과 파일(`eval/results/*.md`), 테스트, 커밋에서 확인할 수 있는 값만 쓴다.
- 기존 항목을 고칠 때는 지우지 않고 ~~취소선~~과 정정 날짜·사유를 덧붙인다.
