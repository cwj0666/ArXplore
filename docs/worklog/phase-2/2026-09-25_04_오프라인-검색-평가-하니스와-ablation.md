title: 오프라인 검색 평가 하니스와 ablation
date: 2026-09-25
area: [eval, tooling]
decision: known-item 질의와 LLM 합성 질의로 lexical·vector·hybrid를 논문·청크 단위 hit@k·MRR@10·recall@10·noise@10·지연으로 비교하고, 다양성·필터·재정렬·가중 RRF를 하나씩 끈 ablation을 함께 돌린다
---

**결정과 근거** — 검색 경로를 바꿔도 좋아졌는지 말할 근거가 없었으므로 오프라인 하니스를 만들었다(985ce4f). 질의는 두 종류다.
known-item(논문 초록으로 그 논문을 찾는 질의)과 chunk_synth(본문 청크 하나로만 답할 수 있게 LLM이 만든 질의, 정답 청크 id
보유). `scripts/eval_build_queries.py`가 표본과 프롬프트를 dry-run으로 보여 주고 `--generate`로 만든 질의는 사람이 검토한다.
`scripts/eval_retrieval.py`가 논문 단위·청크 단위 hit@1/5/10, MRR@10, recall@10, noise@10, 문맥 창 조회까지 포함한 지연
p50/p95를 기록한다. ablation은 `*_nodiv`(논문당 2청크 다양성 제거), `lexical_nofilter`(references·front_matter·outline 필터
제거), `vector_norerank`(Python 재정렬 제거), `hybrid_plainrrf`(가중치·보정 없는 표준 RRF)다. DB에 연결할 수 없거나 정답 id가
DB에 없으면 결과를 쓰지 않고 실패한다.

**트레이드오프** — 질의를 LLM이 만들면 코퍼스 문장을 그대로 옮긴 질의가 섞여 lexical에 유리해진다. 생성기가 원문을 그대로
옮긴 출력과 빈 출력을 거부하고(`test_generate_rejects_verbatim_and_empty_outputs`), 사람이 쓴 케이스(phase-4 카탈로그)를
함께 돌린다. 판정이 정답 id 일치라 "정답은 아니지만 쓸모 있는" 결과는 0점이다.

**eval 영향** — `tests/unit/test_eval_metrics.py`(27개, hit·MRR·recall의 경계와 중복 처리), `tests/unit/test_eval_runner.py`
(36개, ablation 파이프라인과 보고서). 이 하니스로 phase-4에서 146개 질의(LLM 생성 72 + 케이스 74, 정답 논문이 있는 115개로
채점, k=10)를 돌렸다.

**알려진 한계** — 정답 id가 있는 질의만 채점하므로 거절·입력 거부·대화 이력 케이스 31개는 검색 평가에서 빠진다. 청크 단위
지표는 정답 청크가 있는 15개 질의로만 계산되어 표본이 작다.

**트러블슈팅** — 해당 없음
