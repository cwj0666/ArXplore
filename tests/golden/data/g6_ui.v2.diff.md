# G6 화면 골든 v2 변형: 원본과 다른 점

변형 파일은 `g6_ui.v2/<화면>.{txt,aria.yml,png}`이고 v2 캡처와 비교할 때만 쓰인다. 원본 `g6_ui/`는 옛 프론트와 옛 Django 백엔드 기준으로 그대로 둔다. 변형이 없는 화면은 원본과 비교한다.

다시 만드는 명령(저장소 루트, 먼저 `cd frontend && npm ci && npm run build`)
- 비교: `uv run python -m scripts.goldens.capture_g6_ui` 또는 `uv run pytest tests/golden/ui/test_g6_ui_v2.py`
- 변형 저장: `uv run python -m scripts.goldens.capture_g6_ui --out <폴더> --write-variant <화면...>`. 원본과 바이트가 다른 파일만 저장하고, 비교할 때는 파일마다 변형이 있으면 변형을, 없으면 원본을 쓴다.

캡처 방식
- 하네스와 같은 환경의 `arxplore` 명령으로 DB 사본에 `migrate`를 돌린 뒤 `arxplore api`를 `SERVE_FRONTEND_DIST=true`로 띄운다. FastAPI가 v2 빌드와 API를 한 주소에서 낸다. DB는 `arxplore_tpl`에서 복사한 `v2_test_ui_g6`, LLM은 가짜 OpenAI 서버다.
- 서버는 `.env`가 없는 임시 폴더에서 돌고, 그 폴더의 `frontend/dist`가 v2 빌드를 가리킨다.
- 캡처 스크립트의 선택자 두 개(요약 모델 대화상자의 생성 버튼, PDF 패널 표시 대기)는 옛 프론트의 클래스 이름 대신 역할과 id를 쓴다.
- 비교 기준: innerText와 ARIA 스냅샷은 바이트가 같아야 하고, PNG는 달라진 픽셀 수가 0이어야 한다.

이식 동등성: ae59715(동등 이식) 시점에 v2는 11개 화면 모두 원본과 innerText, ARIA 스냅샷, PNG 바이트가 같았다. 이때와 F19·F29 변형은 v2 빌드를 `vite preview`로 띄우고 API를 옛 Django 백엔드로 프록시해 잡았다. 백엔드를 FastAPI로 바꾼 뒤 달라진 화면은 마지막 절에 적는다.

## F19: 검색 0건 문구

- 화면: `list_no_results`
- 서버 응답의 `query`(서버가 trim한 검색어)가 있는데 결과가 0건이면 "검색 결과가 없습니다."를 보인다. 검색어 없이 0건이면 예전처럼 "수집된 논문이 없습니다."다.
- innerText와 ARIA: `수집된 논문이 없습니다.` → `검색 결과가 없습니다.` 한 줄만 바뀐다.
- PNG: 문구 영역 1,674픽셀(x 640~799, y 341~354)만 다르고 나머지는 같다.

## F29 접근성: 카드 링크, 챗 패널 포커스, 라벨

화면 4개의 ARIA 스냅샷만 바뀌고 innerText와 PNG는 원본과 같다(픽셀 차이 0). 그래서 변형은 `.aria.yml`만 둔다.

- `list_default`, `list_search`: 논문 카드
  - 원본은 `article role=link` 카드 안에 PDF 제목 링크가 들어 있는 중첩 링크였다.
  - 이제 카드는 역할 없는 `article`이고, 그 안에 PDF 링크와 상세 링크가 형제로 있다. 상세 링크는 `/papers/<id>/`로 가는 실제 `<a>`이고 이름은 전과 같은 "{제목} 상세 보기"다. 초록·날짜·추천 수가 이 링크 안에 있다.
  - 상세 링크의 `::before`가 카드 전체를 덮어 카드 아무 곳이나 누르면 상세로 간다. PDF 링크는 그 위에 있어 따로 눌린다.
  - 스냅샷: `link "... 상세 보기"` 아래 PDF 링크가 있던 구조가 `article` 아래 `link "{잘린 제목}"`(PDF)과 `link "... 상세 보기"`(`/url` 포함)로 바뀐다. 카드 순서, 텍스트, `::before`·`::after` 문구는 같다.
- `pdf_split_view`: PDF 분할창 닫기 버튼에 `aria-label="분할창 닫기"`를 붙였다. `button "×"` → `button "분할창 닫기": ×`
- `assistant_answer`: 어시스턴트 입력창에 `aria-label="AI 어시스턴트에게 질문하기"`를 붙였다. 전에는 placeholder가 이름이었다. `textbox "연구 주제, 트렌드, 논문을 질문해 보세요."` → `textbox "AI 어시스턴트에게 질문하기"`와 `/placeholder` 줄
- 챗 패널: 열면 입력창으로, Esc나 ×로 닫으면 여는 버튼으로 포커스가 간다. G6 캡처는 스크린샷 전에 포커스를 풀기 때문에 화면 차이가 없다.

G6 밖에서 옛 앱과 나란히 비교한 결과
- 초록 위 호버 오버레이, 제목 호버 툴팁, 카드 키보드 포커스 링은 픽셀까지 같다. 포커스 링은 상세 링크가 포커스를 받을 때 `:has()`로 카드에 그린다.
- 탭 순서가 바뀐다. 전에는 카드 → 그 안의 PDF 링크 순서였고, 이제 PDF 링크 → 상세 링크 순서다.
- 카드 이동은 이제 브라우저 기본 링크 동작이다. Ctrl/Cmd 클릭과 가운데 클릭이 새 탭으로 열리고, Space 키로는 이동하지 않는다(Enter만 이동).

## F29 마크다운: react-markdown 10 + remark-gfm + rehype-sanitize

G6 11개 화면은 이 수정 전후로 innerText, ARIA 스냅샷, PNG가 모두 같다. 두 답변(상세 챗의 문단+목록, 어시스턴트의 굵은 글씨 안 arXiv 링크)이 옛 미니 파서와 같은 DOM 구조로 그려진다. 그래서 새 변형은 없다.

바뀐 동작
- 문법: GFM 표, 기울임, 취소선, 인용문, 중첩 목록, 할 일 목록, 맨 URL 자동 링크가 렌더된다. 표·인용문·가로줄·중첩 목록 여백 스타일을 추가했다.
- 줄바꿈: remark-breaks로 빈 줄 없는 줄바꿈을 `<br>`로 둔다. 전에는 줄마다 별도 `<p>`라 줄 사이에 문단 간격(상세 챗 8px, 어시스턴트 10px)이 있었고, 이제는 한 문단 안의 줄바꿈이라 간격이 없다. 빈 줄로 나뉜 문단은 전과 같다.
- 제목: `#`~`###`은 전처럼 h3~h5로 내리고, 전에는 글자 그대로 보이던 `####` 이상도 h5로 그린다.
- 링크: http(s) 주소만 링크로 만들고 새 탭으로 연다. arxiv.org·www.arxiv.org의 abs/pdf 링크는 전처럼 `/papers/<id>/`로 바꾼다. 상대 경로, mailto, javascript: 등은 링크 없이 글자만 남는다.
- 원시 HTML: 전에는 이스케이프해서 태그 글자를 그대로 보였고, 이제는 sanitize가 태그를 지우고 태그 사이 글자만 남긴다.
- 이미지: `![설명](주소)`는 불러오지 않고 설명 글자만 보인다.
- 코드 블록 innerText 끝에 줄바꿈 한 개가 더 붙는다(화면 픽셀은 같다).

옛 앱과 나란히 비교한 상세 챗·어시스턴트 알림 상태(굵게, 인라인 코드, 번호 목록, 코드 블록, 제목, 링크, 인용 목록)는 픽셀이 같다.

## FastAPI 백엔드: 목록 동률 순서(F32)와 핵심 포인트 번호(F20)

캡처 백엔드를 옛 Django에서 FastAPI로 바꾸자 11개 화면 중 7개가 달라졌다. 프론트 빌드는 같으므로 차이는 모두 이미 G5 변형에 기록된 백엔드 수정에서 온다. 두 번 캡처한 결과는 바이트 단위로 같았다.

- `list_default`, `list_search`: F32
  - 목록은 게시일 내림차순이다. 이 코퍼스는 게시일 값이 275편에 26종뿐이라 같은 날짜의 논문이 많다. 옛 구현은 같은 날짜 안의 순서를 힙 순서에 맡겼고, FastAPI는 `arxiv_id` 내림차순으로 정한다.
  - `list_default`는 첫 쪽 경계에 같은 날짜 구간이 걸려 있어 구성도 바뀐다. `2609.25636`, `2609.26355`, `2609.26457`이 2쪽으로 가고 `2609.26780`, `2609.26793`, `2609.26796`이 1쪽으로 온다.
  - `list_search`(`?q=diffusion`)는 같은 21편의 순서만 바뀐다. 검색어가 한 단어라 F18(모든 토큰 포함, 순서 무관)은 결과 집합을 바꾸지 않는다.
  - 두 화면의 카드 순서는 G5 v2 변형의 `pages:list_default`, `pages:list_query` 응답 순서와 같다.
  - 카드 위치가 바뀌므로 innerText, ARIA, PNG가 모두 달라진다. 변형 ARIA에는 F29의 카드 링크 구조도 그대로 들어 있다.
- `detail_analysis`, `summary_model_dialog`, `summary_result`, `pdf_split_view`, `detail_chat_answer`: F20
  - 가짜 LLM의 핵심 포인트 응답에는 `3. 3.5% 정확도 향상이 이 논문의 핵심 결과입니다.` 줄이 있다. 옛 구현은 번호를 지우면서 `3.5`의 `3.`까지 잘라 `5% 정확도 향상...`을 보였고, 이제는 `3.5% 정확도 향상...`을 보인다.
  - 다섯 화면 모두 innerText와 ARIA에서 이 한 줄만 바뀌고, PNG는 그 글자 영역 2,834픽셀만 다르다. `pdf_split_view` 변형 ARIA에는 F29의 닫기 버튼 이름도 들어 있다.
- 그대로인 화면: `list_no_results`, `not_found_route`, `detail_not_found`, `assistant_answer`
- 화면에 드러나지 않는 수정
  - F21은 상세 요약의 LLM 호출 수만 바꾼다. 화면의 요약은 마지막 병합 호출의 응답이라 같다.
  - AI 캐시 프롬프트 버전 2는 G6에 드러나지 않는다. 골든 DB에서 개요가 캐시된 논문은 4편(`2609.06011`, `2609.24815`, `2609.28470`, `2609.28473`)이고 G6 상세 논문 `2609.27980`은 캐시가 없어, 옛 구현도 개요와 핵심 포인트를 가짜 LLM으로 새로 만들었다. 버전 1 캐시를 다시 만드는 동작은 G5 `analyze:analyze_cached`, `summary:summary_cached`에 기록되어 있다.
